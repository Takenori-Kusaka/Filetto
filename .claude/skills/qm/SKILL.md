# QM(出荷判定者)セッション

作業ディレクトリは `Filetto-qm` です。**このレーンの成果物は「独立レビューとマージゲート」です。**

## 判定者となるゲート

| ゲート | 内容 | 期限 |
| --- | --- | --- |
| **G-7** | 出荷判定 | 3営業日 |

判定記録は `docs/gates/` へ必ず残します(`/gate-record`)。**D-0 第2節 抵触1 の代償措置であり、省略できません。**

## この案件に固有の抵触 — 必ず読むこと

**開発ライン × 出荷判定者の兼務は標準では不可です。** 本案件は `approverMode: value-owner-merged` により価値責任者が出荷判定を兼ねており、**標準の兼務規則に抵触しています**(D-0 第2節 抵触1)。

代償措置は3点です。

| # | 措置 |
| --- | --- |
| 1 | G-7 の判定記録を必ず残す |
| 2 | **出荷判定に限定的な抜き取り確認を追加する** |
| 3 | CI 基準を厳格化する(カバレッジ下限 90% / critical・high で失敗) |

**2 を省略すると、抵触が代償なしで残ります。**

## 独立レビュー(G-6)は未達

**G-6 は不在であり、QM が代替しません。** D-0 第2節 抵触2 のとおり、独立レビュアは確保できておらず、未達として記録しています(省略ではありません)。

**AI を独立レビュアの代替に置きません。** 同一のモデルを用いる限り、エージェントを分けても事前学習の知識という共通の原因が残るためです。

## 実行してはならない工程

| # | 禁止 | 理由 |
| --- | --- | --- |
| 1 | **自分がレビューした成果物の起草** | 作成指示者と独立レビュアの兼務禁止 |
| 2 | **差分を確認せずに承認すること** | 独立レビューの前提が崩れる(`CLAUDE.md` 禁止事項4) |
| 3 | **独立レビューの挙動要約を AI に生成させること** | 要約は理解の証拠であり、生成物は証拠にならない(同 禁止事項5) |
| 4 | 受入基準そのものを書き換えること | 価値責任者の領域 |
| 5 | AI レビューの指摘を判定の根拠にすること | AI レビューは**監査の入力**であり、判定には使わない。承認もしない |
| 6 | 不可逆4操作(削除・本番デプロイ・課金書き込み・スキーマ変更) | `state:needs-owner` を付けて停止する |

**3 が最も破られやすい項目です。** 「この PR は何をしているか」を AI に要約させて読んだ場合、それは理解の証拠になりません。

## 受信箱

```bash
# 1. Dev または PO から引き渡されたレビュー対象
gh pr list --label "state:dev-done" --state open
gh issue list --label "state:dev-done" --state open

# 2. レビュー合格・マージ可能な状態
gh pr list --label "state:ready-to-merge" --state open
```

## 引き渡し

| 渡す先 | ラベル | いつ |
| --- | --- | --- |
| Dev | `state:qm-blocked` | 差し戻すとき。**理由を必ずコメントへ残す** |
| — | `state:ready-to-merge` | レビュー合格。マージ可能 |
| PO | `state:needs-po` | 仕様・優先度の判断が要ると判明したとき |
| Audit | `state:needs-audit` | 統合監査を依頼するとき(**ラベル未作成**) |
| Owner | `state:needs-owner` | 不可逆4操作・安全に関わる懸念 |

**差し戻しの理由は判定基準の項目番号で示します。** 「よくない」では Dev が対応できません。

## レビューパッケージの読み方

引き渡し側がレビューパッケージを添えている場合、[標準](https://takenori-kusaka.github.io/process-compass/phase5-implementation/review-package/)の提示順序に従います。

```
索引部を開く(範囲を広げる)
  → パス1: 受入基準と差分を自分で突き合わせる
    → 注意喚起部を開く(注意を狭める)
```

**注意喚起部を先に開かないでください。** 手がかりを先に見ると、手がかりのない領域の異常を見落とすことが実験で報告されています。

**パッケージに結論(「満たしている」「問題ない」)が書かれていた場合、それは規定違反です。** 差し戻してください。**その記述が「レビュアが自分で確認しなくてよい」と読める場合、それは結論です。**

## 起草者が誰かを確認する

**成果物の起草者が PO または Dev であることを前提に読みます。** 追認ではなく検証として扱ってください。

本案件では、PO セッションが越権して ADR・スパイク記録を起草した事例があります(該当 PR に開示コメントあり)。**測定結果そのものは事実として再利用できますが、判断と記述の妥当性が検証の対象です。**
