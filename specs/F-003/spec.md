# F-003 人と AI が同じ実体を検索する入口

## 背景

**本機能は、2026-08-14 の着手決裁で入れ替わった主訴求の両方を担う**([着手決裁の正本](../../docs/decisions/P-001-kickoff-decision.md) 第3章 / 企画書 v4.0 観点3)。

| 主訴求 | 本機能での担い方 |
| --- | --- |
| **あなたのフォルダの中だけを見て答える** | 検索の実行時に外部ネットワークへ接続しない(基準12) |
| **確かめるべき箇所へ、1クリックで到達できる** | **基準35〜40**(v4.0 で新設。ADR-0017) |

**主訴求2 の根拠は3本ある。**

| 知見 | 出所 | 意味 |
| --- | --- | --- |
| **引用元へのクリックは訪問の1%** | Chapekis et al., IC2S2 2026 | **示しても人は確かめない** |
| **引用があると信頼が上がる。引用がランダムでも同じ。実際に確認すると信頼は有意に低下する** | Ding et al., AAAI 2025 | **引用を出すだけの設計は、確かめられないまま信頼だけを水増しする** |
| **確かめる手間を実際に下げた設計だけが判断を改善する** | Vasconcelos et al., CSCW 2023(5実験・N=731) | **効くのは表示ではなく検証コストの低減** |

**したがって本機能は「不確かさを表示する」で止めない。** **表示から原文の該当箇所へ到達するまでを受入基準に含める。**

**この導線が実際に使われるかは未検証である。** **企画書 v4.0 の中止条件8 が観測する**(起案者自身が1か月で1度も使わなかった場合は中止)。**観測できる形にするため、基準40 で利用を記録する。**

人向けの入口と AI 向けの入口が**同一のファイル資産を共有している**。既存製品は「取り込み口」であってエクスプローラーではない([S0-007](../../docs/spikes/S0-007-value-hypothesis.md) / [S0-013](../../docs/spikes/S0-013-competitor-matrix.md) の実測)。**ただしこれは決裁で主訴求から第二訴求へ降ろした**。12製品の実測で、入れ子フォルダとリネームを備える製品は他にも存在する(RAGFlow)。**残る差分はファイル監視と1クリック導線である。**

対外インターフェースは後続の Chat / Auth が依存する境界である。**あとから変えると全サービスへ波及する。** したがって契約を ADR-0002 で固定する。本仕様は同 ADR の決定4点にもとづく。

| 論点 | 決定 |
| --- | --- |
| 外部が指す識別子 | **安定 ID**。パスは属性にすぎない。安定 ID はメタデータ保管層で発番し、内容ハッシュとは別に持つ |
| ファイル内容の受け渡し | **本文直返しと署名付き URL の両方**。どちらを返すかは要求する側が指定し、サーバは閾値で暗黙に切り替えない |
| MCP の提供形態 | **HTTP を主とし、stdio も提供する** |
| 初回構築中の扱い | **候補に含めず、未完了 N 件を明示する** |

## 受入基準

### 識別子

| # | 型 | 受入基準 |
| --- | --- | --- |
| 1 | ユビキタス | システムは対外へ返す識別子を安定 ID とし、内容ハッシュを安定 ID として返してはならない |
| 2 | イベント駆動 | 原本のパスが変更された場合、システムは当該ファイルの安定 ID を変更してはならない |
| 3 | イベント駆動 | 原本の内容が変更された場合、システムは当該ファイルの安定 ID を変更してはならない |
| 4 | イベント駆動 | 同一の内容を持つ原本が2件存在する場合、システムはそれぞれに異なる安定 ID を割り当てなければならない |
| 5 | ユビキタス | システムは応答にパスを含める場合、パスを識別子ではなく属性として返さなければならない |
| 6 | 望ましくない事象 | 存在しない安定 ID が指定された場合、システムは HTTP 404 を返さなければならない |

### 検索

| # | 型 | 受入基準 |
| --- | --- | --- |
| 7 | イベント駆動 | 利用者または AI エージェントが日本語の自然文で検索を実行した場合、システムは安定 ID・ファイル名・パス・一致した箇所の抜粋を含む候補の一覧を返さなければならない |
| 8 | ユビキタス | システムはゴミ箱内のファイルを検索結果へ含めてはならない |
| 9 | ユビキタス | システムは未処理のファイルを検索候補へ含めてはならない |
| 10 | イベント駆動 | 未処理のファイルが1件以上ある状態で検索が実行された場合、システムは未処理の件数に加えて、未処理のファイルのパスと、未処理である理由の種別を応答へ含めなければならない |
| 11 | イベント駆動 | 読み取れなかったファイルまたは字形の混入が残ったファイルが候補に含まれる場合、システムは付記文言表から選んだ文言を当該候補へ付記しなければならない |
| 11-2 | ユビキタス | システムは付記文言表の保管先を環境変数から読み取り、ソースコード内の定数として持ってはならない |
| 11-3 | 望ましくない事象 | 付記文言表に、システム自身を主語としない項目、または対象の箇所を指す語を含まない項目が存在する場合、システムは起動を中止し、当該項目を標準エラー出力へ記録しなければならない |
| 12 | ユビキタス | システムは検索の実行時に外部ネットワークへ接続してはならない |

**基準10 の手直し(v4.0)**: **「件数のみ」から「どのファイルが、なぜ未処理か」まで踏み込む。** **件数だけでは検証コストを下げない**(Vasconcelos et al., CSCW 2023 の枠組みによる予測。**直接の先行研究・先行事例は確認できていない**)。**理由の種別は F-002 基準25 が記録するものと同一の分類を用いる。**

**基準11・11-2・11-3 の手直し(v4.0)**: **文言を「一人称・具体的」な表現へ確定する。**

**Kim et al., FAccT 2024(arXiv:2405.00623)は、不確実性の言語的表明が利用者の正答率を上げることを示している。** **ただし有意だったのは一人称・具体的な表現のみで、一般表現は非有意である。** **「〜の可能性があります」といった一般表現では効かない恐れがある。**

| 書き方 | 例 | 扱い |
| --- | --- | --- |
| **一人称・具体的** | **「3ページ目の表を、私は読み取れませんでした」** | **採る** |
| 一般表現 | 「内容が正しくない可能性があります」 | **採らない** |

**文言を基準の本文へ直書きしない。** **文言表を外へ出し(基準11-2)、起動時に形式を検査する(基準11-3)。** 文言は運用の中で調整する対象であり、**運用に依存する値をソースコードの定数にしない**(`context/standards/extensibility.md`)。

### 確かめる箇所への到達(v4.0 で新設)

**ADR-0017 により、本節を F-003 へ置く。**

| # | 型 | 受入基準 |
| --- | --- | --- |
| 35 | イベント駆動 | 検索の候補が返された場合、システムは各候補について、一致した箇所を指す原文内の位置を応答へ含めなければならない |
| 36 | イベント駆動 | 基準11 の付記が候補に含まれる場合、システムは当該付記が指す箇所の原文内の位置を応答へ含めなければならない |
| 37 | ユビキタス | システムは基準35・36 の位置を、安定 ID と、F-002 基準30 が定める形式ごとの表現の組で表さなければならない |
| 38 | 望ましくない事象 | 原文内の位置を特定できない場合、システムは位置を特定できないことを応答へ明示し、推測した位置を返してはならない |
| 39 | イベント駆動 | 利用者が WebUI で候補または基準11 の付記を選択した場合、システムは追加の操作を求めずに、原文の当該箇所を表示しなければならない |
| 40 | イベント駆動 | 利用者が基準39 の表示を実行した場合、システムは実行時刻と対象の安定 ID を監査ログへ記録しなければならない |

**基準39 の「追加の操作を求めず」が、1クリックの定義である。** **選択から表示までの間に、利用者の操作を挟まない。**

**基準38 を置く理由を明記する。** **位置を推測して返すと、確かめた先が正しい保証を失う。** **Ding et al., AAAI 2025 は、引用がランダムでも信頼が上がることを示している。** **誤った位置へ到達させる設計は、確かめられないまま信頼だけを水増しする側に落ちる。** **特定できないことを明示するほうが正しい。**

**基準40 は、中止条件8 を観測可能にするために置く。** **記録が無ければ「1か月で1度も使わなかった」ことを確かめられない。** **観測できない中止条件は、中止条件として機能しない。**

**基準37 の変更(v4.1)**: **「ページ番号または先頭からの文字数」から「F-002 基準30 が定める形式ごとの表現」へ改めた。**

**理由は実測である。** **[S0-014](../../docs/spikes/S0-014-position-mapping.md) が得た位置は、元の2種類に収まらなかった。**

| 経路 | 得られた位置 | 元の2種類に収まるか |
| --- | --- | --- |
| `.xlsx` / `.xls` | **シート名 + 行 + 列** | **収まらない** |
| `.docx` | **本文中の通し番号のみ** | **収まらない** |
| `.pptx` / `.pdf` / 画像 | ページ番号 + 矩形 + 文字範囲 | 収まる |

**「先頭からの文字数」でも機械的には表せる。** **しかし利用者がそこからセルへ到達できない。** **確かめる手間を下げることが本節の目的であり、機械が指せることではない**(Vasconcelos et al., CSCW 2023)。

**位置の表現の正本は F-002 側に置く。** **抽出の工程が取得できるものしか、本機能は返せない。**

**`.doc` は位置が出ない。** **基準38 が受け止める。本文は読める。位置だけが出ない。**

**MCP 経路については基準35〜38 が適用される。** **基準39 は WebUI のみを対象とする。** AI エージェントに対する「1クリック」は意味を持たず、**位置を返すところまでが本機能の責務である。**

| 24 | イベント駆動 | **認可の適用が有効な状態で** JWT が付与されていない要求を受けた場合、システムは HTTP 401 を返さなければならない |

| 33 | ユビキタス | システムはローカルポリシーの保管先を環境変数から読み取り、ソースコード内の定数として持ってはならない |
| 34 | イベント駆動 | **認可の適用が有効な状態で**要求を処理した場合、システムは判定に用いたローカルポリシーの版を監査ログへ記録しなければならない |

**基準29 が基準24・25・34 の前提条件である。番号順と適用順は一致しない。**

**クレームの置き方(2026-08-14 に判断記録から本仕様へ移した)**

| 項目 | 決めたこと |
| --- | --- |
| **名前空間** | **`https://filetto.example/claims` の1キーの配下へ、オブジェクトとして束ねる**(RFC 7519 §4.2 の Public Claim Name) |
| **配下のキー** | `scope`(配列)/ `sub_kind` |
| **採らなかった形** | **フラットな Public Claim Name**(トークンサイズが大きい)/ **Private Claim Name**(衝突の危険)/ **名前空間なし**(RFC 7519 §4.3 に反する) |
| 注意 | **Keycloak では名前空間キーのエスケープが要る** |

**スコープの解決は Filetto のローカルポリシーが担う**(基準32)。**JWT のクレームだけでは決まらない。**

**24〜27 の番号と意味を変えていない。** ADR-0004・前提2・[#55](https://github.com/Takenori-Kusaka/Filetto/issues/55)・G-2 の判定記録が参照しているためである。24・25 は条件節を足しただけで、指す事象は変わらない。**28 は「内容の受け渡し」節で既に使われているため飛ばした**([PR #62](https://github.com/Takenori-Kusaka/Filetto/pull/62) で追加)。

| 基準 | 扱い | 根拠 |
| --- | --- | --- |
| **10** | **変更**(件数のみ → どのファイルが、なぜ未処理か) | 決裁 第9章 |
| **11** | **変更**(文言表からの選択へ) | 同上。Kim et al., FAccT 2024 |

| **37** | **変更**(v4.1。位置の表現を F-002 基準30 へ委ねる) | **[S0-014](../../docs/spikes/S0-014-position-mapping.md) の実測。`.xlsx` のセル座標と `.docx` の通し番号が元の表現に収まらなかった** |

**既存の番号は1件も振り直していない。** **変更したのは基準10 と基準11 の本文だけで、両者が指す事象は変わっていない**(件数 → 件数とパスと理由 / 付記 → 文言表から選んだ付記)。

各基準には、違反すると失敗するテストを1つ以上置く。

## スコープ外

- **認証基盤そのもの**。ユーザー登録・パスワード管理・多要素認証は別マイクロサービス(Auth)の責務
- **Chat / LLM 連携の UI**。別マイクロサービス(Chat)の責務
- **マルチテナント**。初版はシングルユーザー。localhost bind を前提とする
- **JWT クレームの設計そのもの**(クレーム名・スコープの表現・検証の責務分界)。ADR-0004 の対象
- **エンドポイントの完全な一覧と OpenAPI 定義**。実装工程で定める
- **MCP ツールの引数スキーマの詳細**。実装工程で定める
- **検索結果の並び替え・絞り込みの UI**
- **汎用のプレビュー表示**(任意のファイルを開いて閲覧する機能)。SC-B(調整枠)。**基準39 が求める「指定された1箇所の表示」とは別である**(前提6)

| 4 | 署名付き URL を発行できる鍵を環境変数から読み取れる | 基準14・16 が実装できない。**ADR-0004 3-2 により、この鍵は JWT の検証鍵とは別体系(短命の HMAC 署名)である** |
| **5** | **抽出の工程が、抽出テキストの各部分と原文内の位置の対応を保持する**(F-002 の責務) | **基準35〜39 が実装できない。** **2026-08-14 に F-002 基準29〜34 として新設した。[S0-014](../../docs/spikes/S0-014-position-mapping.md) が5経路を実測し、`.doc` を除く5形式で取れることを確認した** |
| **6** | **原文の該当箇所を WebUI で表示できる**(PDF はページ、オフィス文書は該当箇所を含む範囲) | **基準39 が実装できない。** **プレビュー表示はスコープ外(SC-B)としているが、基準39 が要求するのは「該当箇所の表示」であり、汎用のプレビューではない** |

**前提5 は F-002 への要求である。** **2026-08-14 に F-002 基準29〜34 として新設した。** **[S0-014](../../docs/spikes/S0-014-position-mapping.md) が5経路を実測し、`.doc` を除く5形式で位置が取れることを確認している。** **`.doc` は基準38 が受け止める。**

**前提6 とスコープ外の「プレビュー表示」の関係を明記する。** **汎用のプレビュー(任意のファイルを開いて閲覧する機能)はスコープ外のままである。** **基準39 が求めるのは、指定された1箇所を表示することだけである。**
