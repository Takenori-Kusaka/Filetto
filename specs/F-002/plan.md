## テストの方針

**テストは実装より先に生成します。実装コードをテスト生成の入力に渡しません。** 実装を読んだうえでテストを書くと、実装の誤りをそのまま正解とみなすテストが生成されます。

| 基準 | テストの種類 | どこに置くか |
| --- | --- | --- |
| 1, 2, 3, 4, 5 | 単体 | `tests/derived/` |
| 6 | **単体(派生物の一覧に画像形式が現れないことの検査)** | `tests/derived/` |
| 7, 7-2 | 結合(実ファイルを入力に) | `tests/parse/` |
| 8, 9, 10 | 結合(実ファイルを入力に) | `tests/parse/` |
| 11 | **結合(外向きの通信を遮断した状態で抽出を通す)** | `tests/parse/` |
| 12 | **結合(API キーの環境変数が無い状態で抽出を通す)** | `tests/parse/` |
| 13, 14, 16 | 単体 | `tests/normalize/` |
| 15 | **単体(対応表を外部の場所から差し替えて結果が変わることを見る)** | `tests/normalize/` |
| 13-2 | 単体 | `tests/normalize/` |
| 13-3 | **単体(confusables を含む入力の出力が入力と一致することを見る)** | `tests/normalize/` |
| 18, 21 | 単体(インターフェースの差し替え可能な実装で) | `tests/index/` |
| 19, 20 | 単体(比率を環境変数で変えて順位が変わることを見る) | `tests/index/` |
| 22 | 結合(追加の前後で既存の索引が残ることを見る) | `tests/queue/` |
| 23 | 結合 | `tests/search/` |
| 24 | **結合(未処理のファイルの語で検索して候補に出ないことを見る)** | `tests/search/` |
| 25 | **結合(必ず失敗する入力を与え、索引に登録されないことを見る)** | `tests/parse/` |
| 26, 17, 27 | 結合 | `tests/search/` |

**基準15 のテストは、対応表を差し替えて結果が変わることを見ます。** 「定数として持っていない」ことを直接は測れないためです。**差し替えで結果が変わるなら、定数ではありません。**

**基準7-2 のテストには、図の中に文字がある画像が要ります。** `spec.md` が挙げている `fig-kakei-02.png`(Docling 経由 23文字 / RapidOCR 直接 394文字)が該当します。**この差が出ない検体を使うと、2経路の比較そのものが検証されません。**

**基準19 のテストはモデルの初回取得(約 1.04 GB)を伴います。** CI で毎回取得すると時間がかかるため、**取得済みモデルを前提にした結合テストと、埋め込み生成を差し替えた単体テストへ分けます。** どちらか一方だけにしません。

## 並行して実行する場合

複数のエージェントを同時に走らせる場合、次を満たします。

- **作業ツリーを分離する。** 同一ディレクトリでの並行実行はファイルの上書きを起こす
- **`src/filetto/parse/**` を同時に変更する組み合わせを避ける。** Task-2 / Task-3 / Task-4 / Task-11 が触る
- **`src/filetto/index/**` も同じ。** Task-7 / Task-8 が触る
- 完了後に、同一機能の重複実装が生じていないかを確認する

**並列可と記した Task-3 / Task-5 / Task-7 / Task-9 / Task-11 も、同じ配下を触るものは同時に走らせません。**
