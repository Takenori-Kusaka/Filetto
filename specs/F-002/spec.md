# F-002 置いた瞬間から読める状態にするインデクシング

## 背景

**探した先でやることは RAG である。RAG に取り込めないなら、見つけても意味がない。**

[S0-004](../../docs/spikes/S0-004-rag-fitness.md) は、検索精度 10/10 の構成が RAG 適合性では 15問中 4問しか正答できないことを実測した。**探せることと使えることは別である。** したがって本機能は「索引に載ること」ではなく「抽出テキストが文脈として使えること」を基準に置く。

構成は ADR-0005 が定めた案B に従う。層A(パース)の出力はミラーディレクトリへ保存し、原本は書き換えない。

初回構築は重い。50 ファイルで約 25 分、数千ファイルなら数時間から十数時間かかる([S0-003](../../docs/spikes/S0-003-parser-and-hybrid.md))。**利用者を待たせない設計と、まだ読めていないことを隠さない設計が要る。**

## 受入基準

### 派生物とミラー

| # | 型 | 受入基準 |
| --- | --- | --- |
| 1 | ユビキタス | システムは派生物を `.filetto/` 配下の単一ディレクトリへ保存し、原本ディレクトリへ書き込んではならない |
| 2 | ユビキタス | システムは派生物の主キーを原本の内容ハッシュとしなければならない |
| 3 | イベント駆動 | 原本のパスが変更された場合、システムは内容ハッシュを変更せず、パスとハッシュの対応のみを更新しなければならない |
| 4 | イベント駆動 | 同一の内容ハッシュを持つ原本が2件以上存在する場合、システムは派生物を1件のみ保持しなければならない |
| 5 | イベント駆動 | 原本が削除された場合、システムは当該原本に対応する派生物を保持しなければならない |
| 6 | ユビキタス | システムはページ画像を派生物として保存してはならない |

### パースと抽出

| # | 型 | 受入基準 |
| --- | --- | --- |
| 7 | イベント駆動 | 拡張子が `.pdf` または画像形式のファイルが投入された場合、システムは Docling と RapidOCR を `force_full_page_ocr` を有効にして呼び出さなければならない |
| 7-2 | イベント駆動 | 図が大きな面積を占める画像が投入された場合、システムは Docling を介さず RapidOCR を直接呼び出す経路でも抽出し、**得られた文字数が多いほうを採用しなければならない** |
| 8 | イベント駆動 | 拡張子が `.xlsx` のファイルが投入された場合、システムは ExStruct を `light` モードで呼び出し、座標付きの構造を行単位のテキストへ線形化しなければならない |
| 9 | イベント駆動 | 拡張子が `.docx` または `.pptx` のファイルが投入された場合、システムは Docling を呼び出さなければならない |
| 10 | イベント駆動 | 拡張子が `.xls` または `.doc` のファイルが投入された場合、システムは xlrd または olefile を呼び出さなければならない |
| 11 | ユビキタス | システムは抽出テキストの生成時に外部ネットワークへ接続してはならない |
| 12 | ユビキタス | システムは抽出テキストの生成時に API キーを要求してはならない |
| 28 | ユビキタス | システムはモデルの取得を起動時に完了し、抽出テキストの生成中にモデルを取得してはならない |

**基準28 は、基準11 と前提1 の境界を定める(v4.1 で新設)。** **前提1 は「初回のモデル取得のためのネットワーク接続が1回だけ確保できる」と述べ、基準11 は「抽出テキストの生成時」の接続を禁じている。** **両者は両立するが、モデルを遅延読み込みすると抽出中に接続が起きる。基準28 がその経路を塞ぐ。**

### 原本内の位置の対応(v4.1 で新設)

**F-003 基準35〜39(確かめる箇所への到達)が、本節に依存する**(F-003 前提5)。

**本節は [S0-014](../../docs/spikes/S0-014-position-mapping.md) の実測にもとづく。** **5経路すべてを実際に動かした結果である。**

| # | 型 | 受入基準 |
| --- | --- | --- |
| 29 | イベント駆動 | 抽出テキストが生成された場合、システムは抽出テキストの各部分と原本内の位置の対応を派生物として保存しなければならない |
| 30 | ユビキタス | システムは原本内の位置を、ファイル形式ごとに定めた表現で保持しなければならない |
| 31 | ユビキタス | システムは位置の対応を、基準8 の線形化より前に取得しなければならない |
| 32 | 望ましくない事象 | 原本内の位置を取得できない経路でファイルが処理された場合、システムは位置を取得できないことを派生物メタデータへ記録し、推定した位置を保存してはならない |
| 33 | ユビキタス | システムは形式ごとの位置の表現の定義を、ソースコード内の定数として持ってはならない |
| 34 | イベント駆動 | 基準7-2 により2つの経路で抽出した場合、システムは採用した経路の識別子を派生物メタデータへ記録しなければならない |

**基準30 の「形式ごとの表現」 — [S0-014](../../docs/spikes/S0-014-position-mapping.md) の実測値**

| 経路 | 位置の表現 | 実測 |
| --- | --- | --- |
| `.xlsx`(ExStruct `light`) | **シート名 + 行番号 + 列番号** | **取れる。線形化の前の JSON に入っている** |
| `.xls`(xlrd) | **シート名 + 行番号 + 列番号** | **取れる** |
| `.pptx`(Docling) | **スライド番号 + 矩形 + 文字範囲** | **取れる** |
| `.pdf` / 画像(Docling + RapidOCR) | **ページ番号 + 矩形 + 文字範囲** | **取れる** |
| **`.docx`(Docling)** | **本文中の通し番号のみ** | **`prov` が全項目で空。`pages` も空。ページ上の位置は取れない。読み順は取れる** |
| **`.doc`(olefile)** | **なし** | **ストリームの一覧と大きさのみ。段落・ページ・文字位置を表す API が無い** |

**`.docx` を「位置が出ない経路」としない。** **本文中の通し番号は、原文の該当箇所を指すのに足りる。** **ページ上のどこかは示せないが、どの段落かは示せる。**

**`.doc` だけが基準32 の対象である。** **本文は読める。位置だけが出ない。** **推定した位置を返すより、位置が出ないことを明示するほうが正しい**([軸5](../../context/standards/product-principles.md) / F-003 基準38)。

**基準31 を置く理由**: **位置は層A がツールから受け取る時点にしか存在しない。** **`.xlsx` を行単位テキストへ線形化した後では復元できない。** **S0-014 で、線形化の前に取れることを確認した。基準8 の設計変更は要さない。**

**基準34 を置く理由**: **基準7-2 は「得られた文字数が多いほうを採用する」と定めている。** **Docling 経由の矩形は4値(`l/t/r/b`)、RapidOCR 直接は4点の多角形である**(S0-014)。**採用した経路によって座標の形が変わるため、どちらを採ったかを記録しないと座標を解釈できない。**

**基準33 を置く理由**: **形式は増える。** **増えるたびにソースコードを変える構造にしない**(`context/standards/extensibility.md` / [軸6](../../context/standards/product-principles.md))。

### 字形の正規化

| # | 型 | 受入基準 |
| --- | --- | --- |
| 13 | イベント駆動 | 抽出テキストが生成された場合、システムは対応表にもとづく字形の正規化を実行しなければならない |
| 13-2 | イベント駆動 | 抽出テキストが生成された場合、システムは Unicode confusables に該当する文字を検出し、当該ファイルの派生物メタデータへ記録しなければならない |
| 13-3 | ユビキタス | システムは Unicode confusables に該当する文字を自動で置換してはならない |
| 14 | ユビキタス | システムは字形の対応表の左辺を、CP932 へエンコードできない CJK 漢字に限定しなければならない |
| 15 | ユビキタス | システムは字形の対応表をソースコード内の定数として持ってはならない |
| 16 | イベント駆動 | 正規化の後に CP932 へエンコードできない CJK 漢字が残った場合、システムは残存した文字と件数を当該ファイルの派生物メタデータへ記録しなければならない |
| 17 | イベント駆動 | 残存した混入があるファイルが検索結果に含まれる場合、システムは当該ファイルに混入が残っていることを結果へ付記しなければならない |

### 検索索引

| # | 型 | 受入基準 |
| --- | --- | --- |
| 18 | イベント駆動 | 抽出テキストが生成された場合、システムは janome による分かち書きの結果から BM25 の索引を構築しなければならない |
| 19 | イベント駆動 | 抽出テキストが生成された場合、システムは multilingual-e5-small による埋め込みを生成し、派生物として保存しなければならない |
| 20 | ユビキタス | システムは BM25 と埋め込みの統合比率を 3 対 7 とし、この値を環境変数から読み取らなければならない |
| 21 | ユビキタス | システムは層B の実装をインデクサ抽象化インターフェースの背後で呼び出さなければならない |

**保管層の構成(2026-08-14 に判断記録から本仕様へ移した)**

| 項目 | 決めたこと | 採らなかったもの |
| --- | --- | --- |
| **メタデータ保管** | **SQLite**(Python 標準ライブラリ。追加コンテナ0) | PostgreSQL・DuckDB。**`docker compose up` 一発の前提のもとで、Lore に続けてコンテナを増やさない** |
| **埋め込みベクトルの置き場** | **同じ DB の BLOB 列 + NumPy の総当たり** | **連結した単一配列**(0.021s と速いが、**行番号とハッシュの対応が壊れると検索結果が別の文書を指す**)/ **DB のベクトル索引**(pgvector は許可ライセンス外、sqlite-vec は pre-1.0) |
| 差し替えの境界 | **薄い境界を置く。移行可能性の規律を守る** | 完全な抽象化(初版では過剰) |

**速度差より、誤りの気づきにくさを避ける。** **本案件は同種の誤り(隣の項目を拾う)を [S0-004](../../docs/spikes/S0-004-rag-fitness.md) で実測している。**

| 23 | イベント駆動 | 未処理のファイルが1件以上ある状態で検索が実行された場合、システムは未処理の件数を検索結果とともに返さなければならない |

## スコープ外

**実測にもとづくもの**([S0-004](../../docs/spikes/S0-004-rag-fitness.md) 検証5 / [S0-006](../../docs/spikes/S0-006-ocr-glyph.md))。

- **原文どおりの文字列を保証すること**。字形の正規化は「日本語に存在しない字」しか直せない。**日本語にある字への誤読(`日`→`目`)は検出できない**(ADR-0011 決定1)。Unicode confusables の検出を加えても、confusables は漢字同士の字形近似を設計上の対象外とするため拾えない
- **レガシー `.doc` の罫線レイアウトの復元**。olefile では表の構造が復元されない
- **ページ画像そのものを対象にした意味検索**。ローカル CPU で 16.7 秒/ページ・日本語 2/5
- **表の完全な意味理解**。ExStruct で 3/3 になったが、評価は 3 問であり一般化の根拠がない

**設計上の判断によるもの。**

- **インデクサの複数実装の同時稼働**。インターフェースは定義するが、実装は案B の構成のみ
- **1つの倉庫内でファイルごとに異なるインデクサを使い分けること**
- **Excel COM(xlwings)経由のパース**。Excel の導入を利用者へ要求する
- **Docling VLM 経路**。予備手段として ADR-0005 に記録するが、初版では呼び出さない

**判定していないこと(対応しないとは書かない)**: 手書き文字を含む帳票、極端に低解像度のスキャン、縦書き文書。S0 のコーパスに含まれず、判定できていない。

### スコープ外から外したもの(2026-08-13)

**「文字がほとんど無い図・グラフ画像からの内容取得」をスコープ外から外した。**

**根拠が崩れたためである。** `fig-kakei-02.png` を「文字がほとんど無い図」と判定していたが、**表題・軸目盛・注釈がすべて描かれていた。** 取れなかった原因は画像ではなく **Docling が図領域内の文字を捨てていたこと**だった。

| | Docling 経由 | RapidOCR 直接 |
| --- | --- | --- |
| 抽出文字数 | 23 | **394**(17.1倍) |
| 正解に必要な文字列 | 0/9 | **9/9** |

**Docling の技術報告が明記している**(`arXiv:2408.09869v5`): "Text content inside figures is currently dropped"

**ADR-0011 決定2 が案2-B(層A の抽出だけを直す)を採ったため、この内容は取得できる。**

**ページ画像の保存は引き続き行わない**(基準6 は維持)。

## 前提

| # | 前提 | 崩れたときの影響 |
| --- | --- | --- |
| 1 | 初回のモデル取得(約 1.04 GB)のためのネットワーク接続が1回だけ確保できる | 基準7・19 が実装できない |
| 2 | 利用者が初回構築の所要時間を受け入れる | 基準22〜24 の設計では体験が成立しない。**未検証**(企画書「未検証の前提」6) |
| 3 | 原本ディレクトリと同じディスクに `.filetto/` を作成できる | 基準1 が成立しない |
| 4 | 内容ハッシュの衝突が実用上発生しない | 基準2・4 が別ファイルを同一視する |
| **5** | **座標を含む位置の対応を保存しても、派生物のサイズが原本の 50% を超えない** | **非機能の要求(資源)に抵触する。** **[S0-014](../../docs/spikes/S0-014-position-mapping.md) は `kakei-02.pdf` の904項目すべてが矩形を持つことを実測した。保存量への影響は測っていない** |
| **6** | **位置の取得を含めた初回構築の所要時間が、前提2 の範囲に収まる** | **利用者を待たせる時間が延びる。** **S0-014 は PDF 1件に252秒を要した。S0-003 の見積(50ファイルで約25分)と整合するかは測っていない** |

**前提5・6 は v4.1 で追加した。** **いずれも [S0-014](../../docs/spikes/S0-014-position-mapping.md) が「判定していないこと」として挙げた事項である。** **`plan.md` で確かめる。**

## 非機能の要求

| 項目 | 要求 |
| --- | --- |
| 応答時間 | 検索は同期で応答する。パースは非同期で実行し、検索の応答をブロックしてはならない |
| 同時実行 | パースの並列度を環境変数から読み取る |
| 監査ログ | パースの開始・終了・失敗について、対象パス・所要時間・使用した経路を記録する |
| 資源 | 派生物のサイズが原本の 50% を超えた場合に記録する。実測では約 25%(50 ファイル 16MB に対しテキスト 4.0MB) |

## コア指定

- [x] **コア機能である**(ADR の添付が G-6 で必須になる)

理由: 抽出テキストの質は、検索精度とは別の基準として持つ(企画書「コア機能の候補」)。ここが崩れると、見つかっても RAG に使えない。
