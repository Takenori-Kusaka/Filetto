### 基準4 を Task-3 に置いた理由

基準4(物理削除 API を WebUI と MCP のいずれにも公開しない)は、**両方の経路が存在してはじめて検証できます。**

Task-2 の時点では MCP の経路が無く、「MCP に公開していない」は経路が無いことによって成立します。**それは基準4 を満たしたことにならず、テストが実装の正しさを検出しません。**

**基準7 は時刻に依存します。** 実時間の経過を待つテストにしません。時刻を注入できる形で実装します。

## 前提の扱い

`specs/F-001/spec.md` の前提4 は次のとおりです。

> JWT クレームによるスコープ制御がゴミ箱内にも適用できる

**この前提は ADR-0004 に依存します。ADR-0004 の決定欄は 2026-08-13 時点で空欄です。**

**ただし本計画の11タスクは、いずれも認可の詳細に依存しません。** 基準2〜12 はゴミ箱の扱いであり、**「誰がアクセスできるか」ではなく「削除が可逆か」を要求しています。**

**前提4 が条件つきになる範囲を記録します。**

| 影響を受けるもの | 内容 |
| --- | --- |
| **本計画のタスク** | **なし。** 11タスクとも認可の実装を含まない |
| F-001 の前提4 | **ADR-0004 決定3-3(stdio の扱い)が「stdio に認可を適用しない」となった場合、ゴミ箱が権限の緩い経路から読める。** ADR-0003 の「削除したファイルが権限の緩い経路から読めてはならない」に抵触する |

**この抵触が起きた場合、直すのは F-001 の実装ではなく ADR-0004 の決定です。** 本計画のタスクを分割・追加する形では解消しません。
