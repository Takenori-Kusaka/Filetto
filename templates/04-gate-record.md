# ゲート判定記録

`docs/gates/<ゲート>-<対象>-<日付>.md` として置きます。例: `docs/gates/g4-F-012-2026-08-08.md`

| 項目 | 値 |
| --- | --- |
| ゲート | G-4 機能仕様承認 |
| 対象 | F-012 |
| 判定者 | <氏名>。**1人**。合議体にしない |
| 判定日時 | YYYY-MM-DD HH:MM |
| 結果 | 通過 / 差し戻し |
| 期限内か | はい / いいえ(超過した場合は日数も) |

## 確認した項目

判定基準のチェックリストです。ゲートごとに項目が異なります。

- [ ] 1.
- [ ] 2.
- [ ] 3.

## 差し戻しの理由

差し戻した場合のみ記入します。**チェックリストの項目番号で示します**。

> 項目2を満たしていません。受入基準3に対応するテストが見つかりません。

「もう少し検討してください」は理由になりません。基準のないゲートは、判定者の属人判断になり、滞留と素通しの両方を招きます。

## 挙動要約(G-6 のみ)

独立レビューでは、レビュアが**自分の言葉で**1〜2文を書きます。

> 招待の一覧に失効の表示を足す変更。取り消し API は失効時に 409 を返すようになった。

**AI に生成させてはなりません**。要約は理解の証拠であり、生成物は証拠になりません。この欄は文書の体裁を整えるためのものではなく、承認者が対象を理解したことの記録です。
