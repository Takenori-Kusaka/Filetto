# ゲート判定記録

`docs/gates/<ゲート>-<対象>-<日付>.md` として置きます。例: `docs/gates/g4-F-012-2026-08-08.md`

| 項目 | 値 |
| --- | --- |
| ゲート | G-4 機能仕様承認 |
| 対象 | F-012 |
| 判定者 | <氏名>。**1人**。合議体にしない |
| 判定日時 | YYYY-MM-DD HH:MM |
| 結果 | 通過 / 差し戻し |
| 期限内か | はい / いいえ(超過した場合は日数も) |

### 判定を待っている間の書き方

**判定前に記録を用意する場合、空欄にしないでください。** 空欄は書き忘れと区別できません。

```
| 判定日時 | 判定待ち(2026-08-14 提示) |
| 結果 | 判定待ち(2026-08-14 提示) |
```

**提示日を書きます。** `record-integrity` が判定期限(既定2日)を過ぎた判定待ちを検出します。**いつから待っているかが分からなければ、放置を検出できません。**

**判定値は「通過」「差し戻し」の2値です。** 3つ目の語を書くと検査が落ちます。

## 確認した項目

判定基準のチェックリストです。ゲートごとに項目が異なります。

- [ ] 1.
- [ ] 2.
- [ ] 3.

## 判定者の記入欄

<!-- spec-lint-ignore start: 判定者が記入した文。標準 5.7.4 により機械で判定しない -->

**判断・理由・条件は、この区間の中に書きます。**

> 判断: <通過 / 条件付き / 差し戻し>
>
> 理由: <判定者の言葉>

<!-- spec-lint-ignore end -->

**この区間は `spec-lint` の検査から外れます。** 標準 5.7.4 が「記述の実質性を機械的に判定して、承認の可否を自動的に決めてはならない」と定めているためです。判定記録は判定が成立した証拠であり、その成立を語句検査が止める構図を作りません。

**区間の外は検査されます。** 受入基準を転記した部分は、転記元と同じ基準で検査されるべきだからです。

**区間を広げすぎないでください。** 外した範囲は `spec-lint` の出力に理由とともに残ります。

## 差し戻しの理由

差し戻した場合のみ記入します。**チェックリストの項目番号で示します**。

> 項目2を満たしていません。受入基準3に対応するテストが見つかりません。

「もう少し検討してください」は理由になりません。基準のないゲートは、判定者の属人判断になり、滞留と素通しの両方を招きます。

## 挙動要約(G-6 のみ)

独立レビューでは、レビュアが**自分の言葉で**1〜2文を書きます。

> 招待の一覧に失効の表示を足す変更。取り消し API は失効時に 409 を返すようになった。

**AI に生成させてはなりません**。要約は理解の証拠であり、生成物は証拠になりません。この欄は文書の体裁を整えるためのものではなく、承認者が対象を理解したことの記録です。
