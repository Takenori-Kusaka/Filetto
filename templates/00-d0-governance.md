# D-0 意思決定・エスカレーション体制図

`docs/D-0-governance.md` として置きます。**規模によらず必須**です。人数が少ないほど兼務が増え、誰が決めるかが曖昧になります。

frontmatter が埋まっていない、または `next_review` を過ぎている場合、`gate-entry` ワークフローが失敗し、企画承認(G-1)の審議を開始できません。

## 1. 役割の割り当て

同じ人が複数の役割を兼ねる場合、**そのことを明記します**。空欄や「未定」を残さないでください。

| 役割 | 担当者 | 兼務 | 備考 |
| --- | --- | --- | --- |
| 事業決裁者 | | | 投資とリリースを決裁する |
| 価値責任者 | | | 何を作るかを決める。G-2 / G-4 の判定者 |
| 技術判断者 | | | どう作るかを決める。G-3 の判定者 |
| 開発者(検証) | | | AI 生成物の検証と理解の維持 |
| 独立レビュア | | | G-6 の判定者。**作成を指示した本人は不可** |
| 出荷判定者(QA) | | | G-7 の判定者。開発ラインとは分離する |
| 文脈オーナー | | | 恒久層コンテキストの維持 |
| AI 維持管理者 | | | 強制層の設定・モデルの版の管理 |

## 2. 兼務の可否

| 組み合わせ | 可否 |
| --- | --- |
| 価値責任者 × 文脈オーナー | 可 |
| 技術判断者 × 開発者 | 可 |
| 技術判断者 × AI 維持管理者 | 可 |
| 価値責任者 × 技術判断者 | 5名未満のみ可 |
| 事業決裁者 × 価値責任者 | 小規模のみ可 |
| **作成を指示した本人 × 独立レビュア(同一成果物)** | **不可** |
| **開発ライン × 出荷判定者(同一案件)** | **不可** |

## 3. 判定の期限

| ゲート | 期限の目安 | 超過したときの扱い |
| --- | --- | --- |
| G-2 要件合意 | 48時間 | エスカレーション。**自動承認にしない** |
| G-3 技術設計判断 | 48時間 | 同上 |
| G-4 機能仕様承認 | 24時間 | 同上 |
| G-6 独立レビュー | 応答1営業日 / 判定2営業日 | 同上 |
| G-7 出荷判定 | 3営業日 | 同上 |

## 4. エスカレーションの経路

| 状況 | 誰へ | いつまでに |
| --- | --- | --- |
| 判定の期限を超過した | | |
| 判定者が不在(休暇・離任) | | |
| 判定者どうしの見解が割れた | | |
| 安全に関わる懸念が出た | | |

## 5. 代行者

判定者が不在のとき、誰が代行するかを定めます。**空欄にしないでください**。定めがないと、不在のたびに滞留します。

| 役割 | 代行者 | 代行できる範囲 |
| --- | --- | --- |
| 価値責任者 | | |
| 技術判断者 | | |
| 出荷判定者 | | |

## 6. 会議体の対応づけ

規模に応じて、設置ではなく既存の制度へ対応づけます。

| 会議体 | 設置 / 対応づけ / なし | 対応づけ先 |
| --- | --- | --- |
| IT 投資委員会(B-1) | | |
| ステアリングコミッティ(B-2) | | |
| 設計審査会(B-3) | | |
| リリース判定会(B-4) | | |

## 7. 承認

| 項目 | 値 |
| --- | --- |
| 承認者 | frontmatter の `approver` と一致させる |
| 承認日 | frontmatter の `approved_at` |
| 承認の範囲 | frontmatter の `approval_scope` |
| 次回見直し | frontmatter の `next_review` |
