# S0-012「どこが不確かかを示す」設計に、根拠は付くか

[S0-010](./S0-010-barrier-decomposition.md) で、日本の最大の障壁が「誤った回答を信じて業務に利用してしまう」(40.5%、米独の2.07倍)と判明しました。

**そして本案件は、偶然ながらその設計を持っていました。**

**本書は、それが研究知見に照らして妥当かを確かめます。**

## 結論を先に

**中程度に強い。ただし訴求の立て方に修正が要ります。**

| # | 結論 |
| --- | --- |
| **1** | **自動置換の禁止(F-002 13-3)は、Unicode 標準規格が独立に同じ結論へ到達している。4基準中で最も強い** |
| **2** | **不確実性の言語的表明が正答率を上げることは、査読論文で示されている。ただし文言に依存する** |
| **3** | **しかし「表示するだけ」では行動が変わらない。** 引用のクリック率は訪問の1%(実ブラウジングログ) |
| **4** | **訴求は「不確かさを表示する」ではなく「確認すべき箇所へ1クリックで到達できる」であるべき** |
| **5** | **そして日本の実測は、訴求の前提とズレている。日本は過信していない。信頼が低くリテラシーが低い** |

---

## 1. 不確実性の提示は、判断を改善するか

### 支持する根拠

| 文献 | 知見 |
| --- | --- |
| **Kim et al., FAccT 2024**<br>[arXiv:2405.00623](https://arxiv.org/abs/2405.00623) | **LLM が一人称で不確実性を述べる("I'm not sure, but...")と、利用者の確信度が下がり、同意率が下がり、課題正答率が上がった**(誤答への依存が減ったため)。**ただし一般視点の表現("It's not clear, but...")は同方向だが有意でなかった。「正確な言い回しが効く」と結論** |
| Steyvers et al., **Nature Machine Intelligence 2025**<br>[arXiv:2401.13835](https://arxiv.org/abs/2401.13835) | **「較正ギャップ」を実証。** 既定の説明では利用者が LLM の精度を過大評価し、**説明が長いほど確信が上がる(精度は上がらないのに)** |
| Zhang, Liao, Bellamy, **FAccT 2020**<br>[arXiv:2001.02114](https://arxiv.org/abs/2001.02114) | **確信度スコアは信頼の較正に有効。** 一方 local explanation は問題ありと結論 |

### 反証・限界

| 文献 | 知見 |
| --- | --- |
| Zhang et al. 同上 | **較正されても人間・AI 合同の性能は改善しなかった。** 改善は**利用者がモデルの誤りを訂正できるドメイン知識を持つ場合に限られる** |
| Poursabzi-Sangdeh et al., **CHI 2021**<br>[arXiv:1802.07810](https://arxiv.org/abs/1802.07810) | **透明なモデルを見せると、情報過多により利用者はモデルの大きな誤りをかえって検出・訂正できなくなった** |
| Bansal et al., **CHI 2021**<br>[arXiv:2006.14779](https://arxiv.org/abs/2006.14779) | **説明は正誤にかかわらず AI の推奨を受け入れる確率を上げた** |

**要約**: **「不確実性を言葉で示す」と「確信度の数値を出す」は支持される。「説明を厚くする」「内部を見せる」は逆効果になりうる。**

## 2. 引用表示 — 「人は確認しない」側の証拠が強い

| 文献 | 知見 |
| --- | --- |
| Liu, Zhang, Liang, **Findings of EMNLP 2023**<br>[arXiv:2304.09848](https://arxiv.org/abs/2304.09848) | Bing Chat / Perplexity / YouChat の人手評価。**引用 recall 51.5%、引用 precision 74.5%。「流暢で情報豊富に見えるが、頻繁に裏付けのない記述と不正確な引用を含む」** |
| **Chapekis et al., IC2S2 2026**<br>[arXiv:2608.04831](https://arxiv.org/abs/2608.04831) | **米国成人900名の代表パネル1か月分の実ブラウジングログ。AI Overview の引用元へのクリックは訪問の約1%でしか発生しない** |
| Łajewska & Balog, **ECIR 2026**<br>[arXiv:2601.14460](https://arxiv.org/abs/2601.14460) | RAG 応答の説明(source attribution / factual grounding / coverage)は**より高品質な応答の選択へ有意に誘導** |
| Onweller et al.(**プレプリント**)<br>[arXiv:2605.06635](https://arxiv.org/abs/2605.06635) | Deep Research エージェントのリンク有効性は 94% 超だが**事実的正確性は 39–77%**。「表層的な引用品質と事実信頼性の乖離」 |

**[S0-011](./S0-011-drop-in-folder-precedents.md) で確認した Ding et al.(AAAI 2025)と合わせると、引用表示の限界が明確です。**

| 発見 | 出典 |
| --- | --- |
| 引用があると信頼が上がる。**ランダムな引用でも同じ** | Ding et al. |
| **実際に引用を確認すると、信頼は下がる** | 同上 |
| **そして人は確認しない(1%)** | Chapekis et al. |
| **引用そのものが壊れている(recall 51.5%)** | Liu et al. |

**「引用がある」ではなく「どこが裏付けられていないか」を示す差別化余地は実在します。**

## 3. 過信を減らす介入 — 効果はあるが代償を伴う

| 文献 | 知見 |
| --- | --- |
| **Buçinca, Malaya, Gajos, CHI 2021**<br>[arXiv:2102.09692](https://arxiv.org/abs/2102.09692) | N=199。cognitive forcing 介入は単純な XAI より**過信を有意に低減。ただし過信を最も減らした設計に、利用者は最も低い主観評価を与えた。** さらに効果は Need for Cognition の高い参加者に偏り、**全員に等しく効かない** |
| **Vasconcelos et al., CSCW 2023**<br>[arXiv:2212.06823](https://arxiv.org/abs/2212.06823) | 5実験・N=731。**過信は費用便益で説明できる。説明が検証コストを十分下げれば過信は減る。** 先行研究の null 結果は「説明が検証コストを下げきれていなかった」ためと解釈 |
| Si et al., **NAACL 2024**<br>[arXiv:2310.12558](https://arxiv.org/abs/2310.12558) | **説明が誤っているときに人は劇的に過信する** |

**Vasconcelos の枠組みが最も実務的です。**

> **説明が検証コストを十分下げれば過信は減る**

**逆に言えば、検証コストを下げない表示は効きません。**

**そして Buçinca の警告が重い。**

> **過信を最も減らした設計に、利用者は最も低い主観評価を与えた**

**「不確かさを示す」を前面に出すほど、購買判断者の主観評価は下がりうる、ということです。**

## 4. OCR の不確実性 — 商用実装では既に標準

| 製品 | 公式の記述 |
| --- | --- |
| **Azure AI Document Intelligence** | フィールド／単語／表・行・セル単位の confidence(0–1)。**「精度が重要な場面では、予測を自動的に受け入れるか人手レビューへ回すかの判定に confidence を使える」** |
| **Amazon Textract** | 全 Block に `Confidence`(0–100) |
| **Google Document AI** | validation filter が confidence 閾値で**文書を人手レビューへルーティング** |

**抽出信頼度の提示と人手レビューへのルーティングは、3社が公式に推奨する既定の運用形であり、業界慣行として定着しています。**

**ただし、その表示が実務で使われているかの独立した評価報告は確認できませんでした。**

## 5. 【最重要】Unicode 標準規格が、自動置換の禁止に同意している

**Unicode UTS #39 Unicode Security Mechanisms**
https://www.unicode.org/reports/tr39/

> skeleton は**文字列の混同可能性を検査する内部用途のみを意図しており、結果のテキストは利用者への表示に適さない**
> **識別子の「正規化」として使ってはならない(should definitely not be used)**

**推奨される扱いは、検出・フラグ・リンク化の抑止であって、置換ではありません。**

**本案件の F-002 基準13-3「confusables を自動で置換してはならない」は、標準規格が独立に到達している結論と一致します。**

**4基準の中で最も強い根拠です。**

### 関連する研究

| 文献 | 知見 |
| --- | --- |
| Yang, Arora, Jheng, Dell<br>[arXiv:2305.14672](https://arxiv.org/abs/2305.14672) | **Vision Transformer で CJK 字形の視覚的類似度を定量化**し、OCR 誤り訂正用の homoglyph 集合を構築 |
| Hemmer et al.<br>[arXiv:2409.04117](https://arxiv.org/abs/2409.04117) | **OCR confidence をトークン埋め込みに統合すると誤り検出性能が向上** |

**日本語 OCR の中国語字形混入を扱った製品・研究は、確認できませんでした。**

## 6. 【前提の修正】日本は過信していない

**KPMG / メルボルン大学 グローバル調査 2025(47か国・48,000人超)の日本スナップショット。**

Gillespie, N., Lockey, S., Ward, T., Macdade, A., & Hassed, G. (2025). *Trust, attitudes and use of artificial intelligence: A global study 2025.*
https://assets.kpmg.com/content/dam/kpmgsites/xx/pdf/2025/05/trust-attitudes-and-use-of-ai-japan-snapshot.pdf

| 指標 | 日本 | 世界平均 |
| --- | --- | --- |
| **AI を信頼する意思がある** | **28%** | **46%** |
| **AI 出力を精度評価せずに依存した** | **56%** | **66%** |
| **AI が原因で業務上のミスをした** | **40%** | **56%** |
| AI で不正確な結果を経験(最上位リスク) | 57% | — |
| AI を適切に使うスキル・知識があると感じる | 43% | — |
| **AI の正式／非公式な研修を受けた** | **22%** | — |
| **AI ツールを効果的に使えると感じる** | **21%** | — |
| オンラインコンテンツが AI 生成かもしれず信用できない | 80% | — |

### この表が、訴求の前提を一部覆す

**日本は「AI を過信している」のではありません。**

**検証せずに依存する割合も、AI 起因のミスも、世界平均より低いです。**

**低いのは信頼(28% 対 46%)とリテラシー(研修 22%、効果的利用 21%)です。**

**つまり IPA が捉えた 40.5% は「実際に過信が起きている頻度」ではなく「過信を恐れている度合い」と読むのが、KPMG の実測と整合します。**

**日本の症状は、過信ではなく、不安による不採用です。**

**なお「なぜ日本で懸念が米独の2倍なのか」を測定に基づいて論じた資料は確認できませんでした。** 通俗的な文化論は除外しています。

## 7. 本案件の4基準の評価

| 基準 | 評価 | 根拠 |
| --- | --- | --- |
| **F-002 13-2** confusables 検出・記録 | **妥当(根拠あり)** | UTS #39 が検出を security screening として位置づけ。Yang et al. が CJK 字形類似度を定量化。Hemmer et al. が confidence 保持の有効性を実証。**ただし検出結果の提示が利用者判断を改善するという直接の人間実験は確認できず** |
| **F-002 13-3** 自動置換の禁止 | **強く妥当** | **UTS #39 が明示的に同じ立場。標準規格が独立に到達している点で、4基準中最も強い** |
| **F-003 基準11** 読み取れなかった旨の付記 | **妥当。ただし文言に依存する** | Kim et al. FAccT 2024 が最も近い支持。**ただし同論文は一人称表現のみ有意で、一般表現は非有意。「〜の可能性があります」といった一般表現では効かない恐れ** |
| **F-003 基準10** 未処理件数の表示 | **方向は妥当だが根拠は確認できず** | **直接の先行研究・先行事例が見つからなかった。** Vasconcelos の枠組みでは「件数だけでは検証コストを下げない」と予測され、**どのファイルが未処理かを特定できなければ効果は薄い可能性** |

## 8. 判定 — 中程度に強い。ただし訴求の立て方に修正が要る

### 強い部分

| # | 内容 |
| --- | --- |
| 1 | **自動置換の禁止は Unicode 標準規格に裏付けられた設計判断であり、単なる方針ではなく規格準拠として主張できる** |
| 2 | **不確実性の言語的表明が利用者の正答率を上げることは査読論文(FAccT 2024)で示されている** |
| 3 | **抽出信頼度の提示と人手レビューへのルーティングは、Azure / Google / AWS の三社が公式に推奨する既定の運用形** |
| 4 | **RAG の引用は現実に壊れている(recall 51.5%)ため、「引用がある」ではなく「どこが裏付けられていないか」を示す差別化余地は実在する** |

### 弱い部分

| # | 内容 |
| --- | --- |
| **1** | **提示しても人は見ない。** 引用クリックは訪問の1%(実ブラウジングログ、N=900)。**「示す」だけでは行動が変わらない** |
| **2** | **過信を最も減らす設計は、最も嫌われる**(Buçinca CHI 2021) |
| 3 | **較正されても成果は改善しない**(Zhang FAccT 2020)。利用者が誤りを訂正できるドメイン知識を持たない限り |
| **4** | **日本の実測データは訴求の前提とズレている。** 日本は過信しておらず、信頼が低くリテラシーが低い |

## 9. 推奨する訴求の修正

### 9-1. 「過信を防ぐ」ではなく「不安があるまま使い始められる」

**KPMG の日本データ(信頼 28%、研修 22%、80%が AI 生成物を信用できないと感じる)が示す症状は不採用です。**

**「どこが不確かかを示す」設計は、その採用障壁の除去策として位置づけるほうが、測定に整合します。**

### 9-2. 「表示する」ではなく「1クリックで到達できる」

**文献が支持しているのは表示ではなく検証コストの低減です。**

**表示だけの設計は、1% クリック率の側に落ちます。**

### 9-3. 受入基準への具体的な影響

| 基準 | 修正の方向 |
| --- | --- |
| **F-003 基準10** | **「件数のみ」から「どのファイルが、なぜ未処理か」まで踏み込むと根拠が強くなる。現状の形のままでは、研究知見上は効果を主張できない** |
| **F-003 基準11** | **文言を検証すること。** Kim et al. の結果は「一人称・具体的」な表現のみが有意だったことを示す。**一般的・受動的な文言では効果を失う恐れ** |
| **新規** | **確認すべき箇所へ1クリックで到達する導線**。現在の受入基準に該当なし |
