# S0-011「フォルダに置くだけ」の先行事例を確かめる

[S0-010](./S0-010-barrier-decomposition.md) で、エクスプローラ思想の仮説が「反証されたのではなく未検証」であることが判明しました。

**本書は、先行事例の結果でそれを確かめます。**

## 結論を先に

**「置くだけ」を主訴求に据えることは、弱いと判定します。**

**理由は3点です。**

| # | 理由 |
| --- | --- |
| **1** | **方向性は業界大手3社が追認済み。ただしそれは「正しさ」ではなく「差別化の土俵ではない」ことを意味する。Windows では OS ベンダ自身が右クリックメニューを押さえた** |
| **2** | **「操作が障壁」という前提が、日本市場については最も弱い。** 日本は国際リテラシー調査で上位であり、S0-010 は障壁が信頼だと既に測っている |
| **3** | **アフォーダンスの証拠が真正面から不利。** 見えている AI ですら気づかれない、という調査がある。**フォルダはボタンより発見可能性が低い** |

**そして、より重要な発見がありました。**

**引用表示は、信頼の較正に効きません。むしろ悪化させます。**(後述 §5)

## 1. クラウドストレージの AI 統合 — 業界は同じ方向へ収斂している

### この表が示す最重要の事実

**業界は「フォルダに置くだけ」の方向へ収斂しています。**

**Dropbox の CEO 発言(2026年)が、本案件の訴求そのものです。**

> AI を、顧客が独立して学習・採用しなければならない**別の目的地として扱うのではなく**、顧客は**知性がコンテンツ操作の native な一部である**ことを期待している

**独立 AI 製品(Dash)を作った当事者が、2年やって native 化へ方針転換しています。**

**Microsoft はエクスプローラの右クリックへ AI を入れ、Google は Drive のフォルダ要約を全有料プランへ同梱し、単体アドオンを廃止しました。**

**訴求の方向性そのものは、世界最大の3社が同じ結論に達しています。**

### しかし「native にしたら使われた」という結果データが、どこからも出ていない

| 社 | 状態 |
| --- | --- |
| **Dropbox** | **「露出は限定的」。収益化を来年以降へ送った**(一次・決算) |
| **Microsoft** | **最も native に置いたにもかかわらず採用率が一桁台**(二次) |
| Google | **非開示** |

**「操作の壁を下げれば使われる」という因果は、データで確認できません。**

## 2. 「ゼロ操作」を極めた製品の末路

| 製品 | 何が起きたか |
| --- | --- |
| **Rewind AI** | **2025-12-19 に Mac アプリを停止。** Meta が Limitless を買収、Pendant も販売停止 |
| **Microsoft Recall** | **プライバシー批判で複数回延期され、強制から opt-in へ後退。** Windows Hello 認証を必須化 |
| LlamaFS | 5.8k stars を集めたが**issue 53件が未処理** |
| Sparkle | 存続中。ただし**ユーザーレビューがほぼ存在しない** |

### ここから読み取るべきこと

**「操作を覚えなくていい」は、裏返すと「何が起きているか見えない」です。**

**Rewind と Recall は、その裏面が致命傷になった事例です。**

**ローカル完結という設計はこの批判への回答になりますが、自動的に回避できるわけではありません。**

## 3. 「チャット UI が障壁」説は、日本には当てはまらない

**Jakob Nielsen「The Articulation Barrier」**(uxtigers.com)

**OECD PIAAC(2012-2017、約25万人)を根拠に次を述べています。**

> 米国・ドイツのような豊かな国でも**人口の半分が低リテラシー**に分類される
> プロンプト駆動型生成 AI を高度に使えるだけの散文記述力を持つのは**20%未満**。**10% が私の最尤推定**

**しかし同じ論文が、こうも書いています。**

> **日本は例外的に良好で、低リテラシー層は 25% のみ**

**注意すべき点が2つあります。**

**Nielsen 自身が「10%」を推定値と明言しています。実測ではありません。**

**そして日本は PIAAC 上位であり、「日本人はプロンプトが書けない」という主張の根拠には、この論文は使えません。むしろ逆向きの証拠です。**

### 逆向きの証拠

| 事実 | 意味 |
| --- | --- |
| **NotebookLM は、明示的な「ソースを追加」操作とチャット UI を持ったまま 17M〜30M MAU に到達**(二次) | **「フォルダに置くだけ」ではないのに、この領域で最も成功している** |
| Gemini アプリは 10億 MAU(一次) | **チャット UI が普及の障壁になっているという事実は、規模のデータからは見えない** |

## 4. アフォーダンス — 最も厳しい証拠

**NN/g「AI Discoverability: Amazon's Mistakes」**(nngroup.com)

> **テストした AI 機能の大半が、発見可能性と発見容易性の両方を欠いていた**

**Amazon の Rufus チャットについて、次が報告されています。**

> **研究者が介入するまで、気づいた参加者はゼロ**

**参加者の発言。**

> 正直、まったく気づきませんでした…確かにすごく役に立つのに、完全に見落としていました

**参加者は、そもそも見慣れたアプリに AI があると予期していません。**

**(定量データ・参加者数の記載はなし。定性調査です)**

### これが本案件の訴求にとって最も厳しい理由

**フォルダにはアフォーダンスがありません。**

**ボタンすらないので、「見ただけで何ができるか分かる」ことは原理的に起こりません。**

**Amazon が画面上に置いたチャットボタンですら誰も気づかなかった、という調査結果に対し、「フォルダに置くだけ」はボタンを置くことすらしていない、という位置づけになります。**

**事業決裁者の指摘「エクスプローラに AI がついて、こんなことができるようになったんだ、ということが直感的にわかる」は正しい問題設定でした。**

**そして本調査は、それが最も難しい部類の課題であることを示しています。**

## 5. 【決定的】引用表示は、信頼の較正に効かない

**Ding et al., "Citations and Trust in LLM Generated Responses", AAAI 2025**
https://arxiv.org/abs/2501.01303

**引用0件/1件/5件、適合した引用とランダムな引用を出し分けた実験です。**

| 発見 | 内容 |
| --- | --- |
| 1 | **引用があると信頼が有意に上昇** |
| **2** | **ただしそれは引用がランダムであっても同じだった** |
| **3** | **参加者が実際に引用を確認すると、信頼は有意に低下した** |

**(参加者数は abstract に記載なし。確認できず)**

### 本案件にとっての含意

**引用表示は、採用率には効くが、信頼の較正には効きません。**

**むしろ「中身を見ていない引用」が信頼を水増しします。**

**S0-010 で判明した日本の障壁「誤った回答を信じてしまう 40.5%」に対し、引用表示は解決策にならず、悪化させうるということです。**

**原文へのリンクを出すだけでは足りません。利用者に実際に原文を開かせる設計が要ります。**

**そして原文を開くと信頼は下がります。それが正しい較正です。**

## 6. 判定 — 弱い

### 訴求が有効だという根拠

| # | 根拠 | 種別 |
| --- | --- | --- |
| 1 | **Dropbox CEO の方針転換発言**。独立 AI 製品を作った当事者が2年やって native 化へ | **一次(決算)** |
| 2 | **Microsoft がエクスプローラの右クリックへ AI を入れた** | 一次 |
| 3 | **Google が Drive のフォルダ要約を全有料プランへ同梱し、単体アドオンを廃止** | 一次 |
| 4 | NotebookLM が示すとおり、**「自分のファイルに根拠を限定して答える」形式には 1,700万〜3,000万 MAU 規模の需要がある** | 二次 |

### 訴求が有効でないという根拠

| # | 根拠 |
| --- | --- |
| **1** | **native 化しても採用されていない。** Microsoft は採用率一桁台、Dropbox は「露出は限定的」で収益化未計上 |
| **2** | **利用者は目の前に置かれた AI 機能に気づかない**(NN/g)。**フォルダはボタンより発見可能性が低い** |
| **3** | **Nielsen の論拠は日本には当てはまらない。** 日本の低リテラシー層は 25% で最良水準 |
| **4** | **最大成功例の NotebookLM は「フォルダに置くだけ」ではない。** 成功要因は操作の少なさではなく**根拠の限定**にある可能性が高い |
| 5 | **Rewind / Recall**: ゼロ操作の極致は、事業停止と信頼失墜による設計後退を招いた |
| **6** | **Ding et al.**: 信頼の問題は UI の引用表示では解けない。**操作の壁を解いても、本当の壁は残る** |

### 総合

**「強い」ではありません。**

**1. 訴求の方向性は業界大手3社に追認されているが、それは「正しさ」ではなく「競合が同じことをやる」ことを意味します。** **エクスプローラのフォルダは差別化の土俵ではなく、既に踏まれた土俵です。Windows では OS ベンダ自身が右クリックメニューを押さえています。**

**2. 「操作が障壁」という前提が、日本市場については最も弱い証拠しかありません。** **この訴求は、測って分かっている一位の障壁ではなく、二位以下の障壁を解く提案です。**

**3. アフォーダンスの証拠が真正面から不利です。** **「置くだけ」は導入摩擦を下げますが、同時に発見の契機を消します。**

## 7. 賭けるなら、こう組み替える

| # | 組み替え |
| --- | --- |
| **1** | **主訴求を「置くだけ」から、根拠の限定へ移す。** 「あなたのフォルダの中だけを見て答える。答えの根拠は必ず元のファイルで示す」 |
| 2 | **「置くだけ」は主訴求ではなく、導入の摩擦説明(第二訴求)として残す** |
| **3** | **引用表示だけで信頼を作らない。** 引用は未検証のまま信頼だけを増やす。**原文を開かせる導線と、根拠が薄いときに答えないことを設計で担保する** |
| 4 | **ローカル完結は Recall の失敗の裏返しとして、そのまま訴求価値になる**(「何も外へ出ない」)。**ここは証拠が強い側** |

**1 の根拠**: **NotebookLM の成功要因も、S0-010 が示す日本の障壁も、こちら側にあります。**

**3 は、本案件の受入基準に直接効きます。** **F-003 基準11(読み取れなかった旨の付記)と基準10(未処理件数の表示)は方向として正しいですが、「原文を開かせる」までは規定していません。**
