## 2. この調査群が何を変えたか — 主訴求「置くだけ」から「フォルダの中だけを見て答える + 確かめる箇所へ1クリック」へ

調査は次の順で連鎖しています。各段が前段の結論を検証し、崩しています。

| 段階 | 記録 | 何を検証したか | 何が崩れたか |
| --- | --- | --- | --- |
| 1 | S0-007 | 「Open WebUI で足りるのではないか」 | 崩れず。ただし「作る理由」は前提(エクスプローラでファイルを動かす)の選択に依存する形へ縮小した |
| 2 | S0-008 | 「外に出せない層は読ませたがっているか」 | 崩れた。需要の根拠が「出せない」ではなく「そもそも使い方がわからない」であると判明した |
| 3 | S0-009 | 「政府の AX 政策が需要の裏付けになるか」(事業決裁者の指摘を受けて実施) | 崩れた。予算の91%は「AIを創る」側で、ローカル完結への言及が政府文書にない |
| 4 | S0-010 | 「エクスプローラ思想(操作の学習コストを下げる)が訴求になるか」(事業決裁者の指摘を受けて実施) | 崩れた、というより「反証」ではなく「未検証」だったと判明。同時に、真の障壁が信頼コストであることが実測(IPA 40.5% 対 米独19.6%)で判明した |
| 5 | S0-011 | 「『フォルダに置くだけ』という主訴求そのものの先行事例」 | 崩れた。Dropbox/Microsoft/Google が同じ方向へ進んでいるが採用率は低く、「置くだけ」は差別化の土俵ではないと判定。S0-011 §7 が「主訴求を『置くだけ』から根拠の限定へ移す」ことを提案した |
| 6 | S0-012 | 「S0-010 が示した『信頼コスト』に対し、本案件が既に持つ『不確実性を示す』設計に根拠が付くか」 | 部分的に崩れた。表示するだけでは引用クリック率が約1%に留まり効果が薄いことが判明し、訴求を「不確かさを表示する」から「確認すべき箇所へ1クリックで到達できる」へ修正する必要が生じた |

**結果として、主訴求の変遷は次のとおりです。**

1. 当初の主訴求案: 「フォルダに置くだけで使える」(操作の容易さ)
2. S0-010・S0-011 により後退: 操作の容易さは測定された一位の障壁(信頼)を解かず、先行3社に既に踏まれた土俵だった
3. S0-011 §7 の提案: 主訴求を「あなたのフォルダの中だけを見て答える。答えの根拠は必ず元のファイルで示す」(根拠の限定)へ移す
4. S0-012 による修正: 「根拠を示す」は表示するだけでは効かないため、「確認すべき箇所へ1クリックで到達できる」という導線の設計まで踏み込む必要がある

## 7. 記録間の矛盾

**S0-010 と S0-012 の間で、同一の数値の検証状態が食い違っています。**

- S0-010 は、IPA『DX動向2025』図表2-12のデータ集PDF(p.75)を200dpiで描画して全数値を読み取り、正誤表も確認したうえで「誤った回答を信じて業務に利用してしまう」日本40.5%/米国19.6%/ドイツ19.6%を**検証済みの数値として**掲載しています。
- ところが S0-012 の「確認できなかった項目」は、同じ図表2-12について「本文p.41の定性記述は確認済み。40.5%/19.6%の数値は画像内にあり未検証」と記載しており、**同じ数値を未検証扱いにしています。**

どちらの記録が最新の検証状態を反映しているか、本索引の作成時点では判断できません。数値そのものはS0-010の記載どおり採用していますが、この食い違いは元記録の是正が要る事項として報告します。
