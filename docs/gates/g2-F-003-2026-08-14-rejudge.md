## 価値責任者が判断する項目 — 3点

**結論は書きません。判断の材料だけを並べます。**

### 判断1 — 基準39「追加の操作を求めず」が検証可能か

**これが「1クリック」の定義です。**

| 事実 | 内容 |
| --- | --- |
| 書いた形 | **「利用者が WebUI で候補または基準11 の付記を選択した場合、システムは追加の操作を求めずに、原文の当該箇所を表示しなければならない」** |
| 検証の方法 | **選択から表示までの間に、利用者の操作が挟まらないこと** |
| **対象外にしたもの** | **MCP 経路。AI エージェントに対する「1クリック」は意味を持たない**(基準35〜38 までが適用される) |

**判断していただきたいのは「この書き方で、後から検証できるか」です。**

**「1クリック」という語を受入基準の本文に使っていません。** クリックという操作に限定すると、キーボード操作やタッチが除外されるためです。**代わりに「追加の操作を求めず」と書きました。** **この言い換えが妥当かどうかも、あわせてご判断ください。**

### 判断2 — 基準11 の文言を、基準の本文へ直書きしないこと

**決裁は「文言を一人称・具体的な表現へ確定する」と定めました。**

**確定した文言そのものは、受入基準に書いていません。** 代わりに次の形にしました。

| # | 内容 |
| --- | --- |
| 11 | **文言表から選んだ文言**を付記する |
| 11-2 | **文言表の保管先を環境変数から読み取る**。ソースコード内の定数として持たない |
| 11-3 | **文言表の各項目が「システム自身を主語とすること」「対象箇所を指す語を含むこと」を起動時に検査する** |

**この形を採った理由**: **文言は運用の中で調整する対象であり、運用に依存する値をソースコードの定数にしないため**(`context/standards/extensibility.md`)。

**この形が抱える弱点も書きます。** **「システム自身を主語とすること」を機械で検査すると、日本語では主語の省略が普通であるため、検査が形式的になりえます。** **例示は `spec.md` に置きましたが、検査の実装方法は `plan.md` で定めます。**

**判断していただきたいのは「決裁が求めた『一人称・具体的な表現へ確定する』を、この形で満たしたと見なせるか」です。**

### 判断3 — F-002 への新しい依存を受け入れるか

**基準35〜39 は、抽出テキストと原文内の位置の対応を必要とします。**

| 事実 | 内容 |
| --- | --- |
| **F-002 の現状** | **位置の対応を保持する受入基準が存在しない** |
| 本仕様での扱い | **前提5 として明記した**(`specs/F-003/spec.md`) |
| **崩れたときの影響** | **基準35〜39 が実装できない** |
| 確かめる時期 | **F-002 の `plan.md` を作るとき** |

**取れない場合は F-002 の G-2 再判定が要ります。**

**判断していただきたいのは「この依存を前提として明記したうえで F-003 を通すか、F-002 側の手当てを先に求めるか」です。**
