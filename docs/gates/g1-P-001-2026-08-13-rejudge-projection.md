# 5. 残すリスクと、残す理由

**「全部潰してから決裁」は成立しません。どこかで「これ以上潰すより赤字を止める」判断が要ります。**

| # | 残すリスク | 顕在化する時期 | 残す理由 |
| --- | --- | --- | --- |
| **1** | **市場仮説が未検証**(第三者が採用し使い続けるか) | 公開後 | **検証の担い手が組織に不在。D-0 で未達として宣言済み**(ADR-0031)。**潰すには公開して観測するしかなく、それは実装の後** |
| **2** | **独立レビュー(G-6)が未達** | 開発〜出荷まで継続 | **1名体制。作成を指示した本人以外が挙動を確認する経路が無い。** 省略ではなく未達 |
| 3 | 初回構築の所要時間を利用者が受け入れるか | 公開後 | 数千件で数時間〜十数時間。**低減策(順次処理 + 未完了の明示)を設計済み** |
| **4** | **自己修正ループ中のテスト改変が機械で止まらない** | 実装開始以降 | **序盤フェーズの最適化のため強制層を外している**([ADR-0015](../../context/decisions/0015-enforcement-scope-during-optimization.md))。**実装工程に入る前に [#75](https://github.com/Takenori-Kusaka/Filetto/issues/75) で戻す** |

**1 と 2 は、投じる額を増やしても潰れません。** **1 は公開しないと観測できず、2 は人を増やさないと成立しません。** どちらも本案件の制約そのものです。

**4 は期限を切っています。** 実装が始まる前に戻します。**戻さないまま実装へ入ると、G-5 の合否が「テストが正しいこと」を前提にしながら、その前提を機械で保証しない状態になります。**

# 6. なぜ収益で説明しないのか

**収益モデルがありません。** 運用費0円、利用者は当面1名、AGPL-3.0 の OSS です。

**一次資料は、それを前提とした枠組みを持っています。**

> OSPO が直接的・分離可能な形で帰属可能な収益を生むことは稀である。財務的貢献は **コスト回避・効率・無駄の削減** を通じて見えることのほうが多い。**これが企業環境で価値を表現する最も信頼できる方法の一つである**
> — Linux Foundation, *Measuring OSPO Value*(2026-06)p.13

> **プロセスやデータが安定する前に、完成した ROI の証明を要求することを避けよ**
> — 同 p.26 Table 3(Stage 1 で避けるべきこと)

**障壁の実測**(LF *2024 World of Open Source*, n=1,264):

| 順位 | 貢献の障壁 |
| --- | --- |
| 1 | 法務・ライセンス懸念 46% |
| 2 | IP 流出の懸念 45% |
| **3** | **ROI が明確に示せない 32%** |

**利用の障壁の第1位は「非技術的な価値提案が理解されていない」56%。**

## 本案件に当てはまる類型

| 類型 | 判定 | 中身 |
| --- | --- | --- |
| **C 標準化・エコシステム影響力(optionality)** | **中核** | **行使価格 = 本人の稼働。取得する権利 = Chat / Auth を含む統合環境への後続投資** |
| **E コア技術の内製化・学習** | 当てはまる | 観点2 の3点が補完資産の主張として書かれている |
| **A サプライチェーン耐性** | **当てはまらない** | **自社が既に依存している OSS を守る論理。新規に作るものには適用できない** |
| B 採用力 / D コスト回避 / F 遵守 / G ブランド | 当てはまらないか、単独では根拠にならない | 1名体制、利用者1名、対象が違う、定性 |

**A を除外した点が重要です。** OSS 投資というと真っ先に挙がりますが、**守る対象が既に存在する場合にしか成立しません。**

## C を主とする理由

> **DCF は「何が起きようと当初計画どおり実行する」と仮定するため、不確実性下の段階的投資を過小評価する**
> — Luehrman, *Investment Opportunities as Real Options*, HBR 1998

**本案件のステージ移行ゲートは、既に段階的オプション行使の構造です。**

```
S0 探索 ──[SG-0]── S1 価値確立 ──[SG-1]── S2 スケール
 通過      通過      いまここ      2026-09末以降
                    各段で中止しうる
```

## E に付す注意

**Nagle, *Management Science* 65(3), 2019 は反対向きの結論も持っています。**

**補完的能力の生態系を持たない企業では、OSS 利用の効果は統計的にゼロでした。**

**本案件は観点2 に3点を書いています**(ピットイン方式の保有 / エージェント側要求の設計者としての理解 / 合成先の全体像)。**これが補完資産に当たります。空欄の案件ではこの類型を使えません。**

# 8. 判断3 の材料 — 累計投入量の上限

**判定者ご自身の仮置きです。**

> **組織のグループ長が扱える金額は社員の年収の10倍までと仮置きすると、役員決裁をかけるまでにかけられる予算は1週間程度。年収を500万とすると、5000万÷12÷4 で100万程度に抑える必要がある**

```
仮置きの上限      100万円
2026-08-13 現在   推定20万円  (20%)

████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  20 / 100 万円
```

**この上限は「使い切ってよい額」ではありません。超える前に決裁をかけるための目安です。**

**残る80%を、決裁後の実装に充てるのか、決裁前の準備に充てるのかが、判断3 の実質です。**

**PO の見立て**: **決裁前の準備にこれ以上充てる理由が見当たりません。** 決裁材料はこの提示で揃っており、**追加のゲート(G-4 の F-002/F-003)は決裁を早めません。**
