# 2. なぜこの3本なのか — 道筋

## G-2 の判定で3つの穴が見つかりました

**2つは価値責任者のレビューで、1つは調査の副産物で見つかりました。**

```
G-2 の判定材料を作る
   │
   ├─ ADR-0004 が未執筆 → tech-advisor へ調査を依頼
   │     └─▶ 調査の副産物として、受入基準の矛盾が5件見つかった
   │            うち「初版に鍵を発行する人がいない」が最も重い
   │
   ├─ 価値責任者が F-002 をレビュー
   │     └─▶ 「誤字をスコープ外にして諦めが早い」
   │         「図を画像のまま渡す運用があるのでは」
   │         「RAG のベストプラクティスを調べたのか」
   │            └─▶ 調べていなかった → tech-advisor へ
   │                   └─▶ スコープ外の前提そのものが崩れた
   │
   └─ 価値責任者が F-003 をレビュー
         └─▶ 「sqlite を仮置きしたまま引きずられないか」
                └─▶ 誰も判断していなかった → tech-advisor へ
                       └─▶ 争点は DB ではなくベクトルの置き場だった
```

**3本とも「決めていなかったことが見つかった」ものです。** 新しくやりたくなったことではありません。

## 何がわかったか — 平たい言い方で

| ADR | わかったこと |
| --- | --- |
| **0004** | **初版には、鍵を発行する人がいない。** その状態で「鍵が無ければ拒否する」と書いたため、**誰も使えない**。加えて **JWT を扱う主要ライブラリに 2026年の重大な脆弱性が複数ある** |
| **0010** | **データベースそのものより、ベクトル(数値の並び)の置き場のほうが効いた。** ファイルを1件ずつ置く案は、1つにまとめる案の**約24,000倍遅い** |
| **0011** | **「文字が取れない図」ではなかった。** 部品(Docling)が**図の中の文字を捨てていた**。直接呼び出すと17倍取れる |

**3本とも、実測または一次情報で裏を取っています。**

## 名指しされた候補は、どれも軽くありませんでした

| 候補 | 誰が挙げたか | 調べた結果 |
| --- | --- | --- |
| **PGlite** | 価値責任者 | **Python から直接使えない。** Node のサーバを立てることになり、Postgres と同じコスト |
| **Aurora DSQL** | 価値責任者 | 外部キー・トリガ・拡張なし。**ローカルで動かす公式の手段が無い** |
| **DynamoDB** | 価値責任者 | ベクトル検索は**有料枠のみ**。加えて**細かい権限制御に非対応**で、受入基準と衝突しうる |
| **誤字チェッカーの OSS** | 価値責任者 | **実際に動かしたが、`日`→`目` を検出できなかった。** 学習データが OCR 誤りではなく人間のタイプミス |

**「調べたら使えなかった」ではなく、「調べたら別の問題が見えた」というものが多いです。**

# 3. いま、何を決めるのか

**45案あります。** 内訳は次のとおりです。

| ADR | 論点 | 案 |
| --- | --- | --- |
| **0004** JWT クレーム契約 | クレーム名 / スコープの表現 / 検証の責務分界 | 12案 + 下位論点3件 |
| **0010** データベース層 | メタデータ保管 / 外部化の境界 / ベクトルの置き場 | 16案 |
| **0011** OCR の誤り訂正と図表 | 誤り訂正 / 図表の扱い | 17案 |

## 各 ADR で最も重い論点

| ADR | 重い論点 | 何が問われているか |
| --- | --- | --- |
| **0004** | **署名鍵をどう配るか** | **対称鍵と非対称鍵を同じ仕組みで併用すると、攻撃の入口を自分で作ることになる**(2026年の実際の脆弱性が示している) |
| **0010** | **ベクトルの置き場** | **1件ずつファイルに置くか、1つにまとめるか。** 24,000倍の差 |
| **0011** | **図表をどう扱うか** | **いま「できない」と書いてある根拠が誤っている。** 訂正せずに確定させると、誤った事実の上に範囲が決まる |

## 決めると何が動くか

| 決定 | 動く先 |
| --- | --- |
| ADR-0004 | **受入基準 F-003 の認可4件** → G-2 の再判定へ |
| ADR-0010 | 受入基準 F-003 の1件(実装名の除去) |
| ADR-0011 | **受入基準 F-002 のスコープ外** → G-2 の再判定へ |

**2本(0004・0011)の決定は、範囲そのものを変えます。** G-2 をもう一度通す必要があります。

# 4. この判定で書いていただくこと

**44行の「採らなかった理由」です。** これが本ゲートの本体です。

**空欄は不備ではありません。この工程の成果物の形です。** 標準は「どの案を選ぶかの理由は、人間が記入しなければならない。**この記入を AI に生成させてはならない**」と定めています。

**44行すべてを埋める必要はありません。** 採らなかった案の理由を書きます。

## AI がここまでやったこと・やらなかったこと

| 誰が | 何を |
| --- | --- |
| `tech-advisor`(AI) | 調べる。実測する。**複数案とリスクを並べる** |
| Dev(AI) | ADR の骨子へ転記する。**理由欄は空欄のまま残す** |
| **技術判断者(人間)** | **どれを採るか決める。理由を書く。判定する** |

**AI が「この案を採るべきです」と書いた時点で、人間の記入は追認に縮退します。** そのため書かせていません。

# 5. 追認が要るかもしれないもの

**可逆性の低い決定は、事業決裁者の追認を要します**(D-0 v1.3)。

| 対象 | 該当しうる ADR | なぜ |
| --- | --- | --- |
| **対外インターフェース契約** | **ADR-0004** | JWT クレームは**後続の Chat / Auth が依存する境界**。あとから変えると全サービスへ波及する |
| **アーキテクチャの分割方針** | ADR-0010 論点2 | 外部化の境界を決めるため |
| **採用済み ADR の置き換え** | ADR-0011 | ADR-0005 を置き換える場合 |

**追認は判定と別の行為です。** 判定記録へ別欄を設けてあります。
