## この G-2 は何のためのゲートか

**「何を作り、何を作らないか」を、後から動かせない形で固定するためのゲートです。**

ここを跨ぐと、以後の工程の問いが変わります。

| | G-2 の手前 | G-2 を跨いだ後 |
| --- | --- | --- |
| 議論の対象 | **何を作るか** | **どう作るか** |
| 「これも作ろう」という要望 | 受け入れられる | **範囲外として扱われる**(G-4 で判定) |
| 作らないと決めたもの | 変更できる | **変更には G-2 の再判定が要る** |

**G-2 を跨いでいない案件では、G-4(機能仕様承認)の判定が成立しません。** 範囲の内か外かを判断する基準そのものが無いためです。

## 差し戻すとどうなるか

**工程が S1 の手前へ戻るのではありません。** 受入基準を直して再提出するだけです。

**通してから直す場合との違いは、「合意した」という記録が残るかどうかです。** 矛盾を含んだまま通せば、記録には「検証可能な基準を確認した」と残ります。

# 2. なぜこの調査をしたのか — 道筋

## 企画時に置いた賭け

企画(2026-08-12 承認)は、**1つの技術的な賭けの上に立っていました。**

> **Graphify(ナレッジグラフを作る技術)を使えば、外部のクラウドサービスを使わずに、日本語の文書を意味で検索できるはずだ**

**この賭けが外れると、企画そのものが成立しません。** 「課金なし・自分のマシンで完結」という中核の訴求が、外部サービスへの従量課金に置き換わるためです。

**そこで、実装に入る前に賭けを確かめることにしました。** これが S0 探索です。

## 調査の道筋 — 何を確かめ、何が起きたか

```
【賭け】Graphify で外部サービスなしの意味検索ができる
   │
   ├─ S0-001 本当にできるか?
   │     └─▶ ✗ 崩れた。LLM が必須で、Excel・PowerPoint・古い Word に対応しない
   │
   ├─ S0-002 では代わりに何ができるか?
   │     └─▶ △ 見つかった。10問中8問正解。費用ゼロ
   │
   ├─ S0-003 精度を上げられるか?
   │     └─▶ ○ 10問中10問正解。費用ゼロ、外部通信なし
   │
   │   ここで価値責任者が問い直した
   │   「探せても、AI がその中身を読めなければ意味がないのでは?」
   │
   ├─ S0-004 探した先で本当に使えるか?
   │     └─▶ ✗✗ 崩れた。検索は10問中10問なのに、
   │            中身を読ませると15問中4問しか答えられない
   │         └─▶ 経路を差し替えて 15問中15問へ。誤答ゼロ
   │
   │   ここで価値責任者が対象利用者を定めた
   │   「日本国内の日本語文書が対象。中国語の字が出るのは欠陥」
   │
   ├─ S0-006 日本語の文書に中国語の字が混ざらないか?
   │     └─▶ ✗ 混ざっていた。13箇所
   │         └─▶ 変換表を1段挟んで 0箇所へ。速度は変わらない
   │
   └─ S0-005 (並行)ファイルの履歴管理を自作せずに済むか?
         └─▶ ○ Lore(Epic Games)を使える。自作しない
```

**2回、前提が崩れました。** どちらも「思っていたのと違った」ではなく、**測って初めて分かったことです。**

## 何がわかったか — 素人向けの言い方で

| # | わかったこと |
| --- | --- |
| 1 | **お金をかけずに、自分の PC の中だけで、日本語の文書を意味で検索できる。** クラウドサービスへの送信も、API の契約も要らない |
| 2 | **企画時に中核と考えていた技術は使えなかった。** 別の組み合わせで目的を達成した |
| 3 | **「探せること」と「AI が読めること」は別だった。** 検索で満点でも、中身を読ませると4分の1しか答えられない構成があった |
| 4 | **紙をスキャンした PDF も読める。** 当初「探せるが読めない」と報告していたが、文字認識の部品を替えたら読めた |
| 5 | **日本語の文書に中国語の字が混ざっていた。** 「事項」が「事项」になる。変換表で 0 にできた |
| 6 | **ファイルの履歴管理は自作しない。** 既存の部品(Lore)を使う |

## 確かめていないこと

**確かめたことと同じだけ重要です。**

| # | 確かめていないこと | 崩れると何が起きるか |
| --- | --- | --- |
| **1** | **最初にファイルを読み込む時間(数千件で数時間から十数時間)を、利用者が我慢するか** | **置いてすぐ使える、という体験が成り立たない。訴求に直結する** |
| 2 | 利用者が Docker(実行環境)を起動できるか | 「エンジニアでなくても使える」が成り立たない |
| 3 | AGPL-3.0 というライセンスが採用の妨げにならないか | 第三者が使わない。**下記の2つの穴が両方とも埋まらない** |
| — | 手書き文字・非常に粗いスキャン・縦書きの文書 | **測っていないので、対応するともしないとも言えない** |

**1 が最も重い未検証です。** 「お金はかからないが、時間はかかる」という性質は、実測で分かっています。**その時間を利用者が受け入れるかだけが分かっていません。**

# 4. このゲートで判定していただくこと

**投資の可否ではありません。** それは SG-1(2026-09 末)です。

**「何を作り、何を作らないか」の3点です。**

| # | 判断 | 平たく言うと |
| --- | --- | --- |
| 1 | 作るものと作らないものの線引き | **できないと分かったことを、できないままにしておいてよいか** |
| 2 | スコープ3層の配分 | **「必ずやる」と約束する範囲を置かない、という進め方でよいか** |
| 3 | **未検証の前提3件** | **確かめていないことを抱えたまま進めてよいか** |

**判断3 が最も重い判断です。**

> **最初の読み込みに数時間かかる。それを我慢する利用者がいるかは確かめていない。それでも作るか。**
