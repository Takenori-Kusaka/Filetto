# 2. この G-4 は何を問うゲートか

**「作れる単位に分かれているか」を問います。「何を作るか」は問いません。**

| | G-2 で決めたこと | **G-4 で決めること** |
| --- | --- | --- |

| 対象 | `spec.md` の受入基準22件 | **`plan.md` の11タスク** |
| 変えられるか | **変えるなら G-2 の再判定** | 実装中に超過したら本計画へ差し戻す |

**受入基準の内容は本判定の対象外です。** G-2 で 2026-08-13 に判定済みです。

## なぜこのゲートが要るか

**受入基準は「完了の条件」であって、「作業の単位」ではありません。**

22件の基準をそのまま1つの実装へ渡すと、変更が大きくなりすぎて**人が読み切れない差分**になります。**本案件は G-6(独立レビュー)が未達であり、差分の大きさがそのまま品質のリスクになります。**

> **G-6 が未達である以上、タスクの粒度が品質そのものになる。**(`context/projects/P-001.md` 運用上の注意7)

**G-4 が守っているのは、この一点です。**

# 4. 判断していただく2点

## 4-1. タスク分解の粒度(判定基準2)

**判断の材料として、粒度に関わる設計上の選択を3つ挙げます。結論は書きません。**

### 選択1 — Task-8 に4つの基準をまとめた

| 基準 | 内容 |
| --- | --- |
| 15 | 上書き更新時に版を保管する |
| 17 | `VersionStore` の背後で呼ぶ |
| 18 | Lore の保管パスは環境変数 |
| 19 | 保管パス未設定なら起動を中止 |

**加えて `docker-compose.yml` の新規作成を含みます**(`loreserver` コンテナの追加)。

**まとめた理由**: `CLAUDE.md`「分割しすぎない」が、**新しいインタフェースを追加する変更は、その利用箇所を同じ変更に含める**ことを求めているため。`VersionStore` の定義だけを先行させると、**呼ぶ側の無いインターフェースが1タスク分残ります。**

**`plan.md` は超過時に「`VersionStore` の定義と利用」と「Lore の設定と起動時検査」へ2分割する条件を書いています。**

**着手前に分けるかどうかは判定者の判断です。**

### 選択2 — 基準4 を Task-3 へ置いた

基準4 は「物理削除 API を WebUI と MCP のいずれにも公開しない」です。

**Task-2(WebUI)の時点では MCP の経路がまだありません。** そこで基準4 を判定すると、**「MCP に公開していない」は経路が存在しないことによって成立します。**

> **それは基準4 を満たしたことにならず、テストが実装の正しさを検出しません。**(`plan.md`)

**両経路が揃う Task-3 まで待つ、という選択です。**

### 選択3 — 「無いこと」を要求する基準への対処

**基準4 と基準12(完全削除の予告を通知しない)は、実装を1行も書かずに通るテストになりやすい形です。**

`plan.md` は先に「あれば失敗する」形のテストを書くとしています。

| 基準 | テストの形 |
| --- | --- |
| 4 | **公開経路の一覧を取得し、禁止された操作が含まれないことを見る** |
| 12 | **通知の送出関数が呼ばれないことを見る** |

**これは `docs/platform/README.md`「黙って通る検査を作らない」と同じ原則です。**

## 4-2. 範囲の判定(判定基準5)

**11タスクすべてが `SC-P` です。SC-B(調整枠)も範囲外も0件です。**

| 用語 | 意味 |
| --- | --- |
| **SC-M** | 合意した範囲の必須部分 |
| **SC-P** | 合意した範囲の計画部分 |
| **SC-B** | 調整枠。落としても合意は崩れない |
| 範囲外 | 合意の外 |

**根拠は `specs/F-001/spec.md` の frontmatter が `scope: SC-P` であり、本計画で範囲を変えていないことです。**

**判断していただきたいのは「11件すべてが SC-P でよいか」です。**

**この判断を機械に委ねません。** 自動生成した候補を人手で検証させた実験(2010年)では、**初期の精度が高い候補を与えられた分析者は品質を下げました。** 機械の出力を人が追認する構成は、人の判断を機械の出力へ引き寄せます。

**機械が確認したのは「空欄が0件であること」だけです。**
