## 価値責任者が判断する項目 — 3点

**ここが本ゲートの判定です。** 機械にも AI にも決められません。

### 判断1: 作るものと作らないものの線引きは、これでよいか(基準3・4)

**判断の材料**

| 仕様 | やること | やらないこと(実測にもとづくもの) |
| --- | --- | --- |
| F-001 | 削除・リネーム・移動・上書きをすべて可逆にする。ゴミ箱30日。Lore でバージョン保管 | バージョン間の差分表示 / 同時編集の排他制御 / バージョンの分岐 / ゴミ箱の一括操作 |
| F-002 | Docling + RapidOCR + ExStruct で抽出。BM25 と e5-small を 3:7。字形正規化 | **原文どおりの文字列の保証**(日本語にある字への誤読は検出できない) / 文字がほとんど無い図(56文字しか取れない) / レガシー `.doc` の罫線 / ページ画像の意味検索(CPU 16.7秒/ページ・精度 2/5) / 表の完全な意味理解(評価3問) |
| F-003 | 安定 ID・検索・本文直返しと署名付き URL・MCP(HTTP 主 + stdio)・JWT 検証 | 認証基盤そのもの / Chat の UI / マルチテナント / OpenAPI 定義 / プレビュー表示 |

**判定していないこと(スコープ外と書いていないもの)**: 手書き文字を含む帳票 / 極端に低解像度のスキャン / 縦書き文書。**S0 のコーパスに含まれず、対応しないと書く根拠がありません。**

**確認していただきたい問い**

- **F-002 の「原文どおりの文字列を保証しない」を、スコープ外として抱えたまま進めてよいか。** 引用・法務用途が使えないことを意味します
- **「判定していないこと」3件を、未判定のまま残してよいか。** 「対応しない」と書けば楽ですが、根拠がありません
- F-002 に「望ましくない事象」型の基準が 0 件であることは、**異常系の受入基準が無い**ことを意味します。これでよいか

### 判断2: スコープ3層の配分でよいか(基準5)

| 層 | 割り当て | 割合 |
| --- | --- | --- |
| **SC-M 確約範囲** | **置かない** | **0%** |
| SC-P 計画範囲 | F-001 / F-002 / F-003 の全体 | 100% |
| SC-B 調整枠 | プレビュー表示、UI の装飾、インデクサ差し替えの実装 | 20%程度 |

**SC-M を置かない理由**: 実装を伴う初めての案件であり、単位期間あたりの完了件数の実績を持ちません。過去案件(process-compass / pit-in-template)はドキュメント主体で外挿できません。

**代わりに「範囲によらず満たす必須制約」5件を課しています**(企画書)。

**確認していただきたい問い**

- **確約する範囲を置かない、という配分でよいか。** 2026-09 末の公開は目標であって確約ではない、という状態が続きます
- **基準5 で割り当てた層が、G-4 における範囲内外の判定の基準になります。** ここで層を割り当てていない案件では G-4 の判定が成立しません

### 判断3: 未検証の前提3件を抱えたまま進めてよいか(基準6)

**これが本ゲートで最も重い判断です。**

| # | 前提 | 崩れたときに起きること |
| --- | --- | --- |
| 4 | 利用者は Docker を起動できる | **「非エンジニアに広げる」という目的が成立しない。** Lore 採用でコンテナが1個増えた |
| 5 | AGPL-3.0 でも個人セルフホストの採用は妨げられない | 第三者の採用が伸びない。**G-6 の未達と市場・顧客仮説の未検証が、どちらも埋まらない** |
| 6 | **初回構築の所要時間(数千件で数時間から十数時間)を利用者が受け入れる** | **投入から検索までの体験が破綻する。企画の訴求に直結する** |

**標準は「前提が崩れていることを理由に判定を停止しません。可視化し、受容の決裁を求めます」と定めています**(全ゲート共通の通過条件)。停止する設計は申告そのものを止め、測定を無効にするためです。

**確認していただきたい問い**

- **3件を未検証のまま受容して進めるか。** 受容する場合、その旨を下欄へ記入してください
- **前提6 を確かめる手段を先に用意すべきか。** 用意するなら、それは G-2 の差し戻しではなく別の作業です
