**G-2 は 2026-08-13 に通過しています。** その後、**作らないと決めていたものを作ることにしました。**

```
2026-08-13  G-2 通過      ← 「文字がほとんど無い図からの内容取得はスコープ外」で合意
     ↓
2026-08-13  G-3 通過      ← ADR-0011 が「Docling の抽出だけ直す」を決定

     ↓
```

**G-2 が守っているのは「何を作り、何を作らないか」の合意です。** 合意の中身が変わったなら、合意し直さないと**誰も同意していない範囲を作ることになります。**

**前回の記録は残します。上書きしません。** 何をどう変えたかを追えなくなるためです。

# 3. 判断は2つです

## 判断1 — 図から文字を取ることにした(F-002)

### 前回、何と言って承認したか

**「文字がほとんど無い図・グラフ画像からの内容取得」はスコープ外。全経路で 56 文字しか取れない実例がある。**

### 何が崩れたか

**「文字がほとんど無い図」という判定が誤っていました。**

```
fig-kakei-02.png
  表題      ある
  軸目盛    ある
  注釈      ある
```

**取れなかった原因は画像ではなく、Docling が図領域内の文字を捨てていたことでした。**

> **Text content inside figures is currently dropped**(`arXiv:2408.09869v5` Docling 技術報告)

### 経路を変えると、どうなるか

| | Docling 経由 | **RapidOCR 直接** |
| --- | --- | --- |
| 抽出文字数 | 23 | **394** |
| | | **17.1倍** |
| 正解に必要な文字列 | **0 / 9** | **9 / 9** |

```
Docling 経由   █░░░░░░░░░░░░░░░░░░░   23 文字
RapidOCR 直接  ████████████████████  394 文字
```

### 加える受入基準

| 基準 | 内容 |
| --- | --- |
| **7-2** | 図が大きな面積を占める画像は、**両方の経路で抽出し、文字数が多いほうを採用する** |
| 13-2 | Unicode confusables を検出し、派生物メタデータへ記録する |
| 13-3 | **confusables を自動で置換してはならない** |

**13-3 が「してはならない」である理由**: 自動置換は、**誤読を別の誤読へ置き換える**可能性があります。検出して知らせるところまでにします。

### 変わらないもの

| # | 内容 |
| --- | --- |
| 1 | **ページ画像は保存しない**(基準6 は維持) |
| 2 | **「原文どおりの文字列を保証すること」はスコープ外のまま。** confusables は**漢字同士の字形近似(`日`→`目`)を設計上の対象外**とするため拾えない |

### 増える負担

**画像1枚につき OCR を2回走らせます。** S0-003 の実測では CPU で 16.7 秒/ページでした。**初回構築の所要時間が延びます。**

**前回の判断3 で受容した未検証の前提6(初回構築の所要時間を利用者が受け入れる)に、直接効きます。**

## 判断2 — 認可を既定で適用しないことにした(F-003)

**本再判定で最も重い変更です。**

### なぜ変えたか

**PO が前回の判定前に申告した欠陥1 です。3つが同時に成立しません。**

```
基準24  JWT が無ければ 401
基準27  Filetto は JWT を発行しない
体制    Auth は Filetto の完了後に開発する
```

**初版を `docker compose up` で起動した利用者は、JWT を発行する主体を持ちません。**

**すべての要求が 401 になり、「1コマンドで立てられ、ファイルを置いた瞬間から検索可能になる」(案件の目的)が初版で成立しません。**

### 採った方向

**基準29(新設): 認可の適用の有無を環境変数から読み取り、既定値を「適用しない」とする。**

```
既定                        環境変数で有効化したとき
─────────────────           ─────────────────────────
認可を適用しない            JWT を検証する
localhost バインドが前提    鍵は利用者が用意する
誰でも全ファイルを読める    スコープ外は 404
```

### 同時に加えた5件

**ADR-0004 の決定に対応します。**

| 基準 | 内容 | なぜ要るか |
| --- | --- | --- |
| **30** | **非対称鍵の公開鍵のみ。HS* と `alg: none` を受理しない** | **PyJWT の CVE-2026-48526 は、対称鍵と非対称鍵を同一システムで併用する構成が攻撃面を作ることを示した** |
| 31 | 公開鍵を環境変数から読み取る | 鍵をコードに置かない |
| 32 | スコープの解決に、クレームとローカルポリシーの両方を用いる | ADR-0004 決定3 |
| 33 | ローカルポリシーの保管先を環境変数から。定数にしない | `context/standards/extensibility.md` |
| 34 | 判定に用いたポリシーの版を監査ログへ記録する | 事後に追える |

### 既存の 24〜27 は変えていません

| 番号 | 変更 |
| --- | --- |
| 24 | **条件節「認可の適用が有効な状態で」を足しただけ。指す事象は同じ** |
| 25 | 同上 |
| 26 / 27 | **変更なし** |

**番号は参照子です。** ADR-0004 が5箇所、前提2、[#55](https://github.com/Takenori-Kusaka/Filetto/issues/55)、G-2・G-3 の判定記録が 24〜27 を参照しています。**振り直すと参照先が黙って別のものを指します。**

**その結果、基準29 が 24・25・34 の前提条件でありながら、番号は後ろに来ます。** 仕様本文に明記しています。

### 採らなかった案

| 案 | 内容 | 退けた理由 |
| --- | --- | --- |
| ア | 利用者が自分で JWT を作り、環境変数で与える | 基準24 は満たすが、**利用者に鍵管理を課す**([[calm-technology]] と緊張) |
| ウ | 「発行しない」を「利用者向けの認証情報の発行を行わない」と読み替える | 基準27 の改訂が要る |
| エ | 初版では認可を実装せず、Auth の合成時に導入する | **ADR-0003 と衝突。** ゴミ箱が権限の緩い経路から読める |

### 判断していただきたいこと

> **既定で認可を適用しない、という状態で公開してよいか。**

**受け入れることになるもの**

| # | 内容 |
| --- | --- |
| 1 | **既定の構成では、到達できる者は全ファイルを読める。** 安全は localhost バインドに依存する |
| 2 | **利用者が誤って外部へ公開した場合、認可は働かない** |
| 3 | 有効化しても、**鍵は利用者が用意する**(基準27 は維持) |

**2 が最も重い点です。**
