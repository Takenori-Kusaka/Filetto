01 結論

訴求を入れ替えます。

1

障壁は「出せない」でも「操作」でもなく、「信じてよいかわからない」でした

公的調査で日本 40.5%、米独 19.6%。全10項目のうち、国際差が最大の項目です。そして本製品は、偶然ながらその設計を持っていました。

2

その設計は、Unicode 標準規格が同じ結論に到達しています

「紛らわしい文字を自動で置き換えてはならない」——規格の原文と、本製品の受入基準が一致します。方針ではなく規格準拠として主張できます。

3

提案：訴求を変え、期間・要員・費用はそのままで実施

6週間・1名・追加支出なし。受入基準を4件だけ手直しします。「やらない」も並べています（10枚目）。

04 日本は過信していない

もう一段掘ると、前提が反転しました。

つまり、こういうことです

公的調査が捉えた「誤った回答を信じてしまう 40.5%」は、実際に起きている過信の頻度ではなく、過信を恐れている度合いです。

日本の症状は、過信ではなく、不安による不採用でした。

だから訴求はこうなります

「過信を防ぎます」ではありません。それは起きていない問題を解く提案です。

「不安があるまま、使い始められます」

80% が「オンラインの内容が AI 生成かもしれず信用できない」と答えている国で、信用を前提にしない道具を出す、ということです。

06 規格が味方している

この設計は、思いつきではありませんでした。
Unicode 標準規格が、同じ結論に到達しています。

skeleton は文字列の混同可能性を検査する内部用途のみを意図しており、結果のテキストは利用者への表示に適さない。
識別子の「正規化」として使ってはならない（should definitely not be used）。 Unicode UTS #39 Unicode Security Mechanisms

本製品の受入基準 F-002 13-3 は、こう書いています。

システムは Unicode confusables に該当する文字を自動で置換してはならない 2026-08-13 に技術判断者が決定。規格を参照せずに、同じ結論へ到達していた
本製品の受入基準研究・規格の裏付け判定
紛らわしい文字を自動で置き換えない Unicode UTS #39 が明示的に同じ立場。規格が独立に到達している 強く妥当
紛らわしい文字を検出して記録する UTS #39 が検出を security screening と位置づけ。CJK 字形の類似度定量化（Vision Transformer）、OCR 信頼度の統合が誤り検出を改善（いずれも査読論文） 妥当
読めなかった箇所を答えに付記する 不確実性の言語的表明が正答率を上げる（FAccT 2024）。ただし一人称・具体的な表現のみ有意で、一般表現は非有意 文言次第
未処理の件数を答えに含める 直接の先行研究を確認できず。「件数だけでは確かめる手間が下がらない」と理論上は予測される 要修正

業界の運用形とも一致します

Azure / Google / AWS の3社が、抽出の信頼度を出して人手レビューへ回す運用を公式に推奨しています。

「精度が重要な場面では、自動的に受け入れるか人手レビューへ回すかの判定に confidence を使える」（Azure 公式）

ただし「表示」だけでは足りません

  • 引用元へのクリックは訪問の 1%（実ブラウジングログ・N=900）
  • 引用はランダムでも信頼を上げる。実際に確認すると信頼は下がる（AAAI 2025）
  • 確かめる手間を実際に下げた設計だけが効く（CSCW 2023・5実験 N=731）
07 既存製品で足りるか

足りません。ただし理由は当初と違いました。

正直に：勝てない点

  • オフライン化は公式対応済み。起動もコマンド1行
  • フォルダ階層・ドラッグ移動・リネームは実在する
  • upstream へ足す道は使えません。CLA が無制限の商用化権を要求し、50ユーザ超では製品名も出せない

そして「置くだけ」は差別化になりません

Dropbox は独立 AI 製品を2年やって native 化へ方針転換。Microsoft はエクスプローラの右クリックへ AI を投入。Google は Drive のフォルダ要約を全有料プランへ同梱。

方向は正しかったが、すでに踏まれた土俵です。しかも大手も採用率は伸びていません（Dropbox「露出は限定的」、Microsoft は一桁台）。

08 三方よし

買い手を、狙い直しました。

買い手よし 狭めた

「外に出せない層」から「不安で使い始められない層」へ。

日本は AI を信頼する意思が 28%（世界 46%）、研修を受けた人が 22%、効果的に使えると感じる人が 21%。

確実に存在する買い手は、起案者本人1名です。市場としての買い手は、公開後に観測します。

売り手よし 維持

自社は「AI に実装させながら品質を落とさない開発の進め方」を標準として公開しています。実装案件で回した実績がありません。

本案件がその1件目です。すでに標準の不足を12件見つけて起票しました。

＋ 日本語文書処理の実測知見（他案件へ転用可）

世間よし 限定

AGPL-3.0 で公開し、囲い込みません。

日本語 OCR の中国語字形混入を扱った製品・研究は、調査範囲で確認できませんでした。ここは空白のままです。

ただし行政向けは、デジタル庁が「源内」を OSS 公開する方針。そちらの空白は政府が埋めます。

引用があると信頼が上がる。ただしそれは引用がランダムであっても同じだった。参加者が実際に引用を確認すると、信頼は有意に低下した。 Ding et al., Citations and Trust in LLM Generated Responses, AAAI 2025

この論文が、本案件の立ち位置を決めました。引用を出すだけの製品は、確かめられないまま信頼だけを水増しします。確かめる手間を実際に下げるところまでやる製品は、まだ見つかっていません。
