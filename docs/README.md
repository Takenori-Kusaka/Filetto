## 決裁の正本と、提示資料

**`decisions/P-001-kickoff-decision.md` が正本です。** **`P-001-kickoff-slides.html` は提示資料です。** **食い違う場合は正本を正とします。**

**提示資料を残す理由**: **判定者が実際に見たものが、判定の証跡だからです。** ゲート判定記録の「提示(投影)」と同じ扱いです。

**HTML である理由**: **組織を跨ぐレビューでは、資料の見た目が理解の効率を決めます。** **レビュー会を「内容を理解する時間」ではなく「本質的な指摘の時間」にするためです。** 内部資料は Markdown で統一しますが、**外部レビュー・決裁の資料は別です。**

**閲覧の方法**: **リポジトリを clone し、`docs/decisions/P-001-kickoff-slides.html` をブラウザで開きます。** **GitHub の blob 表示では描画されません。** **追加のホストは持ちません**([PL-0011](platform/PL-0011-publication-host.md))。

テンプレートは `../templates/` にある。

## D-0 がないと始まらない

`D-0-governance.md` は企画承認(G-1)の前提条件。frontmatter が空、または `next_review` を過ぎていると `gate-entry` ワークフローが失敗する。

規模によらず必須。人数が少ないほど兼務が増え、誰が決めるかが曖昧になるため。
