# 論点1 OCR の誤字・字形の混入を、後処理で直せないか

## 1.1 いま何が起きているかを、測り直した

### 現行の判定方法(CP932)が拾える誤りと、素通りする誤り

S0-006 は「CP932 へエンコードできない CJK 漢字」を混入と定義しました。**この定義が素通りする誤りが、コーパスに実在します。**

| 誤りの種類 | 実例(本検証で新規に検出) | CP932 で検出できるか |
| --- | --- | --- |
| **中国語字形の混入** | 事**项** / 審**查** / 閱覧 / 世**带** / 処方**笺**(S0-006 の 5字種13箇所) | **できる** |
| **仮名 → 漢字の同形異字** | 電子**力**ルテ(正: 電子**カ**ルテ)。`fig-digital-01.png` | **できない**。`力`(U+529B) は CP932 に含まれる |
| **日本語にある字への誤読** | `日` → `目`(S0-006 が japan_PP-OCRv4 で実測) | **できない** |

**「電子力ルテ」は本検証で初めて見つけたものです。** 同一ファイル内に正しい「カルテ」が2回、誤った「力ルテ」が1回出ています。

```
- ①電子カルテの標準化 医療機関等での電子力ルテ情報の共有について、2024年度（令…
                                    ↑ ここだけ漢字の「力」
```

**S0-004 の視覚検索の評価クエリに「電子カルテの標準化」が含まれていました。** BM25 は「電子カルテ情報」でこの箇所に一致しません。**検索の一致に直接効く誤りが、現行の判定方法では 0件と数えられています。**

### スコープ外の記述は、この点で不足しています

F-002 は「日本語にある字への誤読は検出できない」とだけ書いています。**同形異字(仮名→漢字)は別の類型であり、こちらは機械可読の一次データが存在します。** 実測の裏づけがある以上、「実測にもとづくスコープ外」という括りに、この類型は入っていません。

## 1.2 反証: 机上で良く見えた案を、実測で落とした

**提示する前に、3つの案を実測で落としました。**

### 落とした案 (i) 辞書照合(SudachiPy)による未知語検出

**`日`→`目` を検出できません。** 実測です。

```
正 7日以内   -> 7[名詞] | 日[接尾辞] | 以内[名詞]
誤 7目以内   -> 7[名詞] | 目[名詞]   | 以内[名詞]     ← すべて辞書内。未知語ゼロ
正 落札日    -> 落札[名詞] | 日[名詞]
誤 落札目    -> 落札[名詞] | 目[接尾辞]               ← 未知語ゼロ
正 町の休日  -> 町 | の | 休日[名詞]
誤 町の休目  -> 町 | の | 休[接頭辞] | 目[名詞]        ← 未知語ゼロ
```

一方、CP932 が既に拾える誤りは未知語としても出ます(`项` `查要` `带` `笺` がいずれも OOV)。

**つまり辞書照合は、CP932 が拾える集合とほぼ同じものを、より重い処理で拾い直すだけです。** 目的の誤りには効きません。

**副作用も測りました。** 既定経路の出力6件に対する日本語を含む未知語は、ファイルあたり 0〜10件。うち大半は `500万` `1億` `アジャイル` `マイナンバーカード`(の分割断片)といった正当な語です。**誤検出のほうが多い水準です。**

> **注記**: 調査担当は SudachiPy の OOV 判定 API の存在を一次情報から確認できないと報告しました。**本検証は `Morpheme.is_oov()` が sudachipy 0.6.11 で動作することを実行で確認しています。**

### 落とした案 (ii) 2つの認識モデルの不一致を疑い箇所とする

**PP-OCRv6(既定)と japan_PP-OCRv4 を同じ検出枠に対して走らせ、不一致した枠だけを疑い箇所にする**という案です。追加モデルは 9.8MB のみ、LLM 不要、外部通信なし。**机上では最も筋が良く見えました。**

**2通りの測り方で、いずれも成立しませんでした。**

| 測り方 | 対象 | 結果 |
| --- | --- | --- |
| ① 文字列差分(行の並びを揃えない) | scan-kaminokawa-03.pdf | **48区間・のべ 837文字が不一致。v6 出力の 49.6%** |
| ② **検出枠を揃えた比較**(det モデルは両経路とも同一の `PP-OCRv6_det_small`) | 同上 | **131枠中 77枠が不一致(58.8%)。** 所要 111.6秒 |

**①は行分割の差が混ざるため不公平でしたが、②で枠を揃えても 58.8% でした。** 不一致の中身は誤りではない差が大半です。

```
v6 = また、変更契約により請負金額の増額があつた場合、…
v4 = また、変更契約により請負金額の増額があった場合、…      ← 促音「っ」の表記差。誤りではない
```

**文書の6割が疑い箇所になり、利用者へ提示する情報として成立しません。** 同じ実行で CP932 混入は v6 が 3件、v4 が 0件でした(S0-006 の傾向と一致)。

**加えて、この案は 1ページあたり 2つの認識モデルを走らせるため、所要時間が増えます。** 上記の測定では 3ページで 111.6秒でした。

### 落とした案 (iii) 日本語の誤字検出器を使う(`recruit-jp/japanese-typo-detector-roberta-base`)

**日本語の誤字脱字検出のために作られた既製モデルです。** 文字単位の token-classification で、9種の誤りカテゴリ(`deletion` / `insertion_a` / `insertion_b` / `kanji-conversion_a` / `kanji-conversion_b` / `substitution` / `transposition` / `others`)の確率を各文字へ出力します。**テキストを書き換えません。** 用途としては最も素直な候補でした。

**実測の結果、目的の誤りを検出できませんでした。**

| 入力 | 最大の誤り確率 | 閾値 0.5 超の文字数 |
| --- | --- | --- |
| 正: `落札日（入札日）より7日以内（初日不算入・町の休日を除く）` | `町` **0.349** | 0/29 |
| **誤: `落札日（入札目）より7目以内（初目不算入・町の休目を除く）`** | `町` **0.043** | **0/29** |
| 正: `医療機関等での電子カルテ情報の共有について` | `テ` 0.006 | 0/21 |
| **誤: `医療機関等での電子力ルテ情報の共有について`** | `テ` **0.487** | **0/21** |
| 正: `共通事項（契約保証金）` | `証` 0.015 | 0/11 |
| **誤: `共通事项（契約保証金）`** | **`项` 0.995** | **1/11** |

**`日`→`目` については、誤った文のほうが正しい文より誤り確率が低く出ています**(0.043 対 0.349)。**検出できないだけでなく、信号の向きが逆です。**

**「電子力ルテ」は信号が出ますが、位置がずれています。** 上がったのは `力` ではなく2文字先の `テ`(0.006 → 0.487)で、しかも閾値 0.5 に届きません。

**確実に検出できたのは `项` だけで、これは CP932 が既に拾える類型です。**

| 項目 | 値 |
| --- | --- |
| ライセンス | **CC BY-SA 4.0**(HF API で確認、2026-08-13)。ベースの `ku-nlp/roberta-base-japanese-char-wwm` から継承。**CC BY-NC-SA・gemma のいずれにも該当せず商用可。ただし SA が付く** |
| サイズ | **398.3MB**(HF API の実測) |
| 最終更新 | **2023-12-21** |
| 速度(実測) | 5〜31 文字/秒。**OCR(112 文字/秒)より遅い** |
| 学習データ | 京大の日本語 Wikipedia 入力誤りデータセット v2。**OCR 誤りではなく「人間のタイプミス」です。** これが `日`→`目` に効かない理由と整合します |

**したがって「日本語の誤字脱字チェッカーの OSS を使う」という方向は、既製品をそのまま当てる形では成立しませんでした。**

> **補足**: 調査担当が Hugging Face を `japanese typo` / `japanese gec` / `ocr correction japanese` / `japanese proofreading` / `校正` で検索した結果、日本語の該当モデルは **2件のみ**でした。もう1件(`mbyhphat/t5-japanese-typo-correction`)は**ライセンス記載なし**のため候補から外れます。**`japanese gec` の検索結果は 0件です。** また **国立国会図書館(ndl-lab)は OCR 後処理の誤り訂正モデルを公開していません**(全44リポジトリの列挙による不在確認、2026-08-13)。

## 3.1 反証で崩れなかった項目(採用側に有利な材料として、正直に記します)

**調査担当に「崩しにいけ」と指示した結果、崩れなかったものです。**

| 項目 | 崩れなかった理由 |
| --- | --- |
| **BM25:dense = 3:7 という比率そのもの** | Bruch et al. は **RRF より線形結合が優れる**とし(NDCG で 5/5 データセット、p<0.01)、**推奨レンジ α∈[0.6, 0.8]** を示しています。**3:7(α=0.7)はレンジの中央です。** 攻撃できるのは「正規化しているか」と「3:7 の根拠を測ったか」の2点のみ |

## 3.2 評価セットの規模について(本案件の全 S0 に効きます)

**S0-003 の 10クエリ、S0-004 の 15問という規模は、一次文献の基準に照らして小さいものです。**

| 一次情報 | 内容 |
| --- | --- |
| BEIR(`arXiv:2104.08663` v4 / NeurIPS 2021) | **最小のデータセットですら Touche-2020 が 49クエリ、TREC-COVID が 50クエリ** |
| Voorhees & Buckley, SIGIR 2002 | 25トピックで 95% の一致を得るには MAP 絶対差 8〜9% が必要。**最低25、望ましくは50** |

## 5.4 可逆性(下書き)

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | **案1-A / 1-B / 2-A / 2-B は可逆。** 案 2-C は **F-002 基準6 と ADR-0002 の両方に触れるため変えにくい**。案 1-D は抽出テキストを書き換えるため実質的に非可逆 |
| 変えるとしたら必要なこと | **いずれの案も派生物(抽出テキスト・埋め込み)の再構築が要る。** 50ファイルで約25分、数千件で数時間から十数時間(S0-003) |
| いつまでなら安く変えられるか | **利用者の倉庫が育つ前まで**(ADR-0005 と同じ。再構築のコストは保管量に比例する) |

## 5.5 非機能への影響(下書き)

| 項目 | 影響 |
| --- | --- |
| 性能 | 案1-B・2-B は速度への影響がほぼない(実測)。**案1-C はバッチ化後でも 112字/秒 → 4.6字/秒(実測)。初回構築の前提6 を直撃する** |
| 資源 | 初回 DL の増分: 案1-B **+0.73MB** / 案1-C **+413MB** / 案1-D +300〜1,600MB / 案2-B **0** / 案2-C **0**(VLM を使わない場合)。**案2-C は派生物のサイズを増やす(未測定)** |
