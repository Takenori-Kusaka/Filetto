# 投入量の台帳

**標準 7.7.2 が定める予算統制の指標を計算するための実測を、時系列で残します**([#107](https://github.com/Takenori-Kusaka/Filetto/issues/107))。

| 指標 | 定義 |
| --- | --- |
| 予算消化率 | 消化した予算 ÷ 配賦した予算 |
| **消化進捗比** | **予算消化率 ÷ 進捗率。1を超えるほど計画より費用が先行している** |
| AI実行予算の消化率 | 月次の実消費 ÷ 月次の配賦額 |

**1回だけ数えて終わると、次に気づくのはまた誰かが手で数えたときです。** 推移が見えなければ消化進捗比は計算できません。

## 測り方

| # | 項目 | 取り方 |
| --- | --- | --- |
| 1 | マージ済み PR の分類 | `node scripts/gate/investment-measure.mjs`(機械) |
| 2 | 行数 | 同上(機械) |
| 3 | AI の使用量 | `--ai-usage ~/.claude/projects` を付けて**手元で**実行(§AI 実行費) |
| **4** | **稼働時間** | **人が書く。機械では取れない** |
| **5** | **AI 実行費(金額)** | **人が書く。§AI 実行費** |

分類規則は `scripts/gate/investment-classes.json` にあります。**一致しないファイルがあると検査は失敗します。** 規則を増やさずに新しい領域が増えると、内訳が実態とずれたまま「測った」記録が残るためです。

### AI 実行費

**トークンの量は取れます。金額は取れません。**

セッション記録(`~/.claude/projects/<作業ツリー>/*.jsonl`)に、応答ごとの `usage` が入っています。**ただしこの記録は利用者のマシンにあり、リポジトリにも CI にもありません。** そのため CI では測れず、**手元で `--ai-usage` を渡したときだけ**出ます。

**金額は契約形態(定額枠か従量か)で決まり、記録には入っていません。** 人が書きます。

**精度より、記録が存在することのほうが重要です。**

### #107 の手集計との差

**PO が手で数えた値と、機械の値は一致しません。** 分類の境界が違うためです。

| 区分 | #107(手) | 本台帳(機械) | 差の理由 |
| --- | --- | --- | --- |
| プロセス | 37件(58%) | 24件(36%) | **手集計は「プロセス系 ADR」を広く採った。** 機械は `investment-classes.json` に列挙した6本の ADR だけをプロセスとする |
| プロダクト | 20件(31%) | 36件(54%) | 同上の裏返し |
| ゲート記録 | 6件(9%) | 6件(9%) | 一致 |
| 実装コード | 1件 | 1件 | 一致 |

**どちらが正しいかではなく、境界の定義の問題です。** 機械の側は `investment-classes.json` に書いてあり、**変えれば次回から反映されます。**

**「プロセス自身の整備コストがどの予算区分にも属していない」という [process-compass#240](https://github.com/Takenori-Kusaka/process-compass/issues/240) の論点3 は、どちらの数え方でも成立します。**
