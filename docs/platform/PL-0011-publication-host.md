# PL-0011: 決裁資料・レビュー資料の置き場を決める

対象 Issue: [#115](https://github.com/Takenori-Kusaka/Filetto/issues/115)
作成: 2026-08-14 / レーン: Platform

## 1. 決定 — 案「甲」を採ります

**決裁資料・レビュー資料は、リポジトリ内の Markdown に置きます。** git ホストのレンダリングで読みます。**追加のホストを持ちません。**

| 論点 | 決定 |
| --- | --- |
| 1 置くホスト | **リポジトリ内(`docs/`)。追加ホストなし** |
| 2 公開範囲の既定値 | **リポジトリの権限そのもの。** 別の権限系を持ち込まない |
| 3 `docker compose` で立つこと | **不要になりました。** 立てるものがありません |
| 4 図表 | **Mermaid。** GitHub がレンダリングします |
| 5 機械で検査できるか | **一部できます。§3 に限界を書きます** |

## 2. 乙・丙を採らなかった理由

### 乙(GitHub Pages)は、今回と同じ事故が別の経路で起きます

**Pages の可視性は、リポジトリの可視性とは別に設定します。** PO の指摘のとおりです。

**今回の事故の本質は「組織が制御できない場所に置いた」ことではなく、「置き場の可視性を、誰も意図して決めていなかった」ことです。** 可視性の設定が2系統あると、**片方だけ意図して決める**という同じ形が再現します。

**本リポジトリは公開なので、いま Pages を有効にしても情報は出ません。** ただし**テンプレートとして他案件へ配る前提**では、非公開リポジトリで使われます。**そのとき Pages の設定を誤ると、非公開の内容が公開されます。**

### 丙(Actions の artifact)は恒久性がありません

**90日で消えます。** 決裁記録は後から参照するためのもので、**参照先が消える置き場は決裁の入力に使えません。**

### 甲の失うもの

**スライド形式の見た目です。**

**本案件では決裁資料を4回作り直し、3回が棄却されました。** 最終的に拠り所になったのは正本の Markdown(`docs/decisions/P-001-kickoff-decision.md`)です。**見た目が決裁の質を上げた形跡がありません。**

**正本が2つになることも避けられます。** 別形式を作ると、どちらが決裁の対象かが曖昧になります。

## 3. 機械で検査できるか — **一部できます。全部はできません**

**PO が「3 が本質」と書いた点です。正直に切り分けます。**

| 何を止めたいか | 機械で止まるか | 手段 |
| --- | --- | --- |
| リポジトリに組織外ホストへの参照が残ること | **止まる** | `external-host-check`(本 PR) |
| **エージェントが外部へ発行すること** | **止まる。ただし設定の変更が要る** | `.claude/settings.json` の `permissions.deny` に `Artifact` |
| 人が手で外部へ貼ること | **止まらない** | — |

### 3-1. 検査(本 PR で入れました)

`scripts/gate/external-host-check.mjs`。`docs/` `specs/` `context/` `templates/` と README 類を走査し、**組織の管理外のホストへの参照を落とします。**

```
検査したファイル: 101 件
検出するホスト: 14 件
理由を添えて除外した行: 0 件
組織の管理外のホストへの参照: 0 件

【この検査の限界】見つけられるのはリポジトリに残った参照だけです。
発行そのものは検出できません。発行の遮断は .claude/settings.json の permissions で行います
```

**限界を毎回出力します。** **「検査が通ったから外部へ出していない」と読まれると、検査が実態より広い保証をしているように見えるためです。**

**今回の事故は、発行してもリポジトリに痕跡が残らなかったために、起票まで誰も気づきませんでした。** 本検査は**その事故を検出できません**。次に URL を記録へ書いたときに初めて当たります。

**事故の記録として URL を書く必要がある場面はあります。** 行末へ理由つきの注記を置けば除外します。**理由の無い注記では除外しません。**

### 3-2. 発行の遮断(Owner の判断が要ります)

**エージェントの発行手段そのものを塞げます。**

```json
"permissions": { "deny": ["Artifact"] }
```

**ただし [ADR-0015](../../context/decisions/0015-enforcement-scope-during-optimization.md) と衝突します。**

> 序盤フェーズの間は `deny` を空のまま運用します

**ADR-0015 は「遮断の範囲を最適化中は縮める」という判断で、`Artifact` の発行を想定していません。** 本件は**新しく起きた事故に対する新しい統制**であり、ADR-0015 の射程外だと考えます。**ただし「deny を空で運用する」という文言には反します。**

**判断は Owner にお願いします。** 変更内容は `docs/platform/proposed/settings.json` に用意しました。

**適用しない場合、発行の抑止は指示の遵守だけになります。** **今回の事故は、規則も検査も無かったから起きました。** 規則(本 PL と Issue #115)は残りますが、**遮断が無ければ同じ手段が使えるままです。**

## 4. 図表について

**Mermaid を使います。** GitHub は Markdown 内の ```mermaid フェンスをレンダリングします。**図も Markdown に収まり、正本が1つのままです。**

**Mermaid で表せない図(写真・詳細な画面設計)は、画像としてリポジトリへ置きます。** 外部ホストへは置きません。

## 5. 検証

```
$ node scripts/gate/external-host-check.mjs   → 101 ファイル、0 件検出
$ pytest tests/gate                           → 全件通過
$ ruff / spec-lint / double-encoding          → 緑
```

| # | 確かめたこと | 結果 |
| --- | --- | --- |
| 1 | **本件で使われたホストへの参照は落ちる**(事例そのもの) | 落ちた |
| 2 | 一覧にある他の組織外ホストも落ちる | 落ちた |
| 3 | 理由を添えれば除外され、理由が出力に残る | 通った |
| 4 | **理由の無い注記では除外されない** | 落ちた |
| 5 | 0件でも件数を出力する | 出た |
| 6 | **検査の限界を毎回出力する** | 出た |
| 7 | **ホスト一覧が空なら落ちる** | 落ちた |
