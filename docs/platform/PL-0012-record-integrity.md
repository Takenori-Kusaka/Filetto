# PL-0012: 記録を落としても検出される検査を置く

対象 Issue: [#145](https://github.com/Takenori-Kusaka/Filetto/issues/145)
作成: 2026-08-14 / レーン: Platform

## 1. 何を置いたか

**`scripts/gate/record-integrity.mjs`。依頼の5件を1つの検査にまとめました。**

| # | 検査 | 検出するもの | 事例 |
| --- | --- | --- | --- |
| 1 | 判定記録の空欄 | 判定日時・結果が空欄のまま `main` にある | 事例1 |
| 2 | 台帳と Issue の整合 | 状態語と Issue の開閉が食い違う | 事例2 |
| 3 | 承認欄と判定記録の整合 | 「通過」と書くのに判定記録が無い / 結果が空欄 | 事例3 |
| 4 | 判定値の語彙 | 標準に無い語 | 事例4 |
| 5 | 期限超過 | 期限を過ぎた行が未返却のまま | — |

**5件を別々のスクリプトにしませんでした。** どれも同じファイル(判定記録・台帳・`spec.md`)を読むためです。**5回読み直す構成にすると、様式が変わったときの直し忘れが5倍になります。**

**すべて G-5 の合否条件です。** いずれも**記述の実質性を判定しません**(標準 5.7.4)。空欄か、語が一致するか、参照先が存在するかだけを見ます。

## 2. 判定記録かどうかを、パスで決めていません

`docs/gates/` には判定記録と提示資料が混在しています。

**中身で決めます。** 見出しの表に「ゲート」と結果欄(`結果` または `判定`)の両方があるものを判定記録とします。**提示資料は結果欄を持たないため、自然に外れます。**

```
判定記録: 8 件(判定記録でない 5 件)
  判定記録として扱わない: docs/gates/g1-P-001-2026-08-13-rejudge-projection.md
  ...
```

**外したものを必ず出力します。** 判定記録が誤って外れていれば、この一覧で気づけます。

**`CLAUDE.md` は「判定はファイルパスではなく変更の性質で行う」としています。** パスで決めると、様式の違う記録を足すたびに規則の改訂が要ります。

### 実装で1件やり直しました

**最初の実装は、3列以上の表の見出し行を「項目 → 値」として拾っていました。**

```
| ゲート | 問い | 誰が決めるか | 状態 |
```

この行を「ゲート = 問い | 誰が決めるか | 状態」と読み、**提示資料を判定記録と誤認しました。** 2列の表だけを拾うよう直しています。

## 3. 検査4 の語彙は、ゲートの種別ごとに持ちます

**G ゲートと SG(ステージ移行)ゲートで、書いてよい語が違います。**

| ゲート | 許す語 |
| --- | --- |
| `G-*` | 通過 / 差し戻し |
| `SG-*` | S1 へ移行 / 継続検証 / 中止 |

**語彙が定義されていないゲートも落とします。** 新しい種別のゲートを足したとき、語彙を書かずに任意の語を書ける状態を作りません。

## 4. 検査2 は双方向に見ます

**台帳の状態語と Issue の開閉は、対応するべきものです。**

| 状態 | 意味 | Issue |
| --- | --- | --- |
| 未返却 | 対処していない | **開いている** |
| 記録済み / 返却済み | 成果物は `main` にある | **閉じている** |

| 食い違い | 何が起きたか |
| --- | --- |
| 未返却 なのに Issue が閉じている | **台帳が古い**、または Issue を早く閉じた |
| 記録済み / 返却済み なのに Issue が開いている | **閉じ忘れ**(事例2) |

**片方向だけ見ると、事例2 を拾えません。**

## 5. 検査5 は、読めなかったことを数え上げます

**台帳の期限は自由記述の場合があります。**

```
期限が日付として読めない行: 3 件
  D-001 期限「`plan.md` の作成前」。日付ではないため期限超過を判定していません
```

**黙って飛ばしません。** 「期限超過0件」だけを出すと、**期限を判定できていない行があることが記録に残りません。**

**日付でない期限を落とすことはしません。** `plan.md` の作成前、という書き方は標準が禁じていないためです。**判定できないことを出力するに留めます。**

## 6. Issue を取得できないときは、実施したことにしません

```
## 検査2 台帳と Issue の整合: 実施できません
  Issue の一覧を取得できませんでした(...)
```

**取得できないことを理由に「0件」と出しません。** `secretScan` が空の設定で通過し続けた前例と同じ穴を作らないためです。

## 7. 検証

```
$ node scripts/gate/record-integrity.mjs
  → 判定記録 8 件・台帳 3 行を検査、0 件検出 (exit 0)
$ pytest tests/gate   → 全件通過
$ ruff / spec-lint / double-encoding / external-host → 緑
```

否定側9件:

| # | 壊し方 | 対応する事例 | 結果 |
| --- | --- | --- | --- |
| 1 | **判定日時を空欄にする** | **事例1** | 落ちた |
| 2 | 結果を「—」にする | 事例1 | 落ちた |
| 3 | **結果を「条件付き通過」にする** | **事例4** | 落ちた |
| 4 | **承認欄が「通過」だが判定記録が存在しない** | **事例3** | 落ちた |
| 5 | 承認欄が「通過」だが参照が無い | 事例3 | 落ちた |
| 6 | **未返却なのに Issue が閉じている** | — | 落ちた |
| 7 | **記録済みなのに Issue が開いている** | **事例2** | 落ちた |
| 8 | 期限を過ぎて未返却のまま | — | 落ちた |
| 9 | 3列表の見出しを持つ提示資料を置く | — | 通った(誤検出しない) |

**一時ディレクトリへ写して壊しています。本物の記録は書き換えていません。**

## 8. この検査で防げないこと

**記録が「書かれているか」しか見ません。**

| 防げる | 防げない |
| --- | --- |
| 判定記録が空欄のまま `main` にある | **判定していないのに「通過」と書く** |
| 承認欄が判定記録を指していない | **判定記録の内容が判定基準と対応していない** |
| 台帳と Issue の食い違い | **台帳に載せるべき事項を載せていない** |

**右列は、記述の実質性の判定です。** 標準 5.7.4 が機械に委ねてはならないとしている領域であり、**本検査は踏み込みません。**

**「検査が通ったから記録は正しい」とは読めません。** 通ったのは「空欄でない・語が一致する・参照先がある」ことだけです。
