# PL-0010: 到達検査が、自分の起動タイミングで誤検出していた

対象 Issue: [#118](https://github.com/Takenori-Kusaka/Filetto/issues/118)
作成: 2026-08-14 / レーン: Platform

## 1. 何が起きたか

**`merged-reachability` が PR #110 を「main へ到達していない」と誤って報告しました。** 起票は本検査の自動起票によるものです。

**実際には到達しています。**

```
$ git merge-base --is-ancestor cfa054c1 origin/main && echo 祖先である
祖先である
```

## 2. 原因は、私が入れた検査の設計です

**PR の一覧は実行時に取るのに、git の履歴は起動した push の時点で固定されます。**

| 時刻 | 出来事 |
| --- | --- |
| 04:23:34 | PR #103 がマージされ、`push: [main]` で本検査が起動 |
| 04:23:37 | 実行開始。`actions/checkout` が **この時点の main** を取得(head=5cbf9fa0) |
| **04:23:40** | **PR #110 がマージされる** |
| その後 | 検査が `gh pr list` を引く → **#110 は一覧に現れるが、履歴には無い** |

**3秒の差です。** 実行記録で確認しました(run 31769723136 / created 04:23:37、PR #110 merged 04:23:40)。

**マージが連続すると必ず起きます。** 本案件はマージが立て込むため、再発します。

## 3. 直した内容

| # | 変更 | 効果 |
| --- | --- | --- |
| 1 | **実行時に `git fetch origin main` する** | checkout の固定を解く |
| 2 | **判定に締め切りを置く** | 取り直してもなお残る隙間を塞ぐ |

### 締め切り

**基準ブランチの先端の時刻より後にマージされた PR は判定しません。**

```
判定の締め切り: 2026-08-14T04:54:58.000Z(origin/main の先端の時刻)
締め切りより後にマージされ、判定を保留した PR: 0 件
```

**取り直しだけでは不十分です。** `fetch` と `gh pr list` の間にもマージは入りうるためです。**締め切りは、その隙間を「判定しない」と明示することで塞ぎます。**

**保留は黙って通しません。** 件数と PR 番号とマージ時刻を出力します。**次回の実行では締め切りが進むため、そのとき判定されます。**

## 4. 保留が抜け道にならないこと

**「保留」は判定の放棄になりえます。** そのため否定側で確かめています。

| # | 確かめたこと | 結果 |
| --- | --- | --- |
| 1 | **締め切りより後のマージは保留する**(未到達にしない) | 通った |
| 2 | **締め切りより前のマージは判定する**(到達していなければ落ちる) | 落ちた |
| 3 | 保留が0件でも件数を出力する | 出た |
| 4 | **締め切りの時刻を出力する** | 出た |

**2 が要です。** 保留の仕組みが、本来落とすべきものまで通していないことを確かめています。
**4 は、いつ時点の履歴で判定したかが残らないと、保留の妥当性を後から確かめられないためです。**

## 5. 検証

```
$ node scripts/gate/merged-reachability.mjs
  → 78 件を検査、到達 75 件、別経路で到達済み 3 件、保留 0 件、未到達 0 件 (exit 0)
$ pytest tests/gate   → 82 passed
$ ruff / spec-lint / double-encoding → すべて緑
```

## 6. 同じ機序を持つ検査

**`pr-base-check` は [PL-0007](PL-0007-pr-base-check-fresh-body.md) で直しました。** イベントのペイロードが古い、という別の形の同じ問題です。

| 検査 | 古くなるもの | 直し方 |
| --- | --- | --- |
| `pr-base-check` | PR の本文とマージ先 | 実行時に API から取り直す(#119) |
| `merged-reachability` | git の履歴 | 実行時に fetch し、締め切りを置く(#118) |

**どちらも「実行時に取り直す」が答えでした。** 起動時の値を当てにしないことです。
