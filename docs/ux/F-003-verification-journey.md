## 判断の基準は1本だけ

**文献が支持しているのは、表示を増やすことではありません。**

> **確かめる手間を実際に下げた設計だけが判断を改善する**(Vasconcelos et al., CSCW 2023。5実験・N=731)

**この1本で決めます。** 迷った場合は「利用者の手間が増えるか減るか」だけを見ます。

**根拠を補強する2本**

| 知見 | 出所 | 本書への影響 |
| --- | --- | --- |
| **引用元へのクリックは訪問の1%** | Chapekis et al., IC2S2 2026 | **導線を1本に絞る。選択肢を増やさない** |
| **引用があると信頼が上がる。引用がランダムでも同じ** | Ding et al., AAAI 2025 | **誤った位置へ到達させない**(論点3) |

## 論点1 — 何が選択可能な対象か

### 候補

| 案 | 選択可能な対象 | 手間 |
| --- | --- | --- |
| 甲 | 候補の行全体 | **1回。ただし「どこを確かめるか」が指定できない** |
| **乙** | **抜粋と、基準11 の付記。それぞれが個別に選択可能** | **1回。確かめたい箇所を直接指せる** |
| 丙 | 候補の行全体 + 抜粋 + 付記(3種すべて) | **選択肢が3つになる。どれを押すか迷う** |

### 決定 — 乙

**選択可能な対象は2種類です。**

| # | 対象 | 対応する受入基準 | 到達先 |
| --- | --- | --- | --- |
| **1** | **一致した箇所の抜粋**(基準7 が返すもの) | **基準35** | **一致した箇所** |
| **2** | **基準11 の付記**(読み取れなかった / 字形の混入が残った) | **基準36** | **その付記が指す箇所** |

**候補の行全体は選択可能にしません。**

**理由**: **行全体を押せると、「ファイルを開く」と「確かめる箇所へ行く」が同じ操作になります。** **前者は既存のファイルマネージャの操作であり、後者が本機能です。** **同じ操作に2つの意味を持たせると、どちらが起きたのかを利用者が予測できません。**

**丙を採らない理由**: **選択肢を3つ置くと、クリック率1%の側へ落ちる可能性が上がります。** **Chapekis の測定は「押せる引用リンクが存在しても押されない」ことを示しています。** **押せる場所を増やしても、押される回数は増えません。**

## 論点2 — 表示がどこへ出るか

### 候補

| 案 | 表示先 | 元の候補一覧へ戻る手間 |
| --- | --- | --- |
| 甲 | **同一画面内の並置パネル** | **0回。一覧が消えない** |
| 乙 | 同一画面内の全面表示(一覧を覆う) | **1回(閉じる)** |
| 丙 | 別タブ | **1回(タブを戻す)。ブラウザの外の操作になる** |

### 決定 — 甲(同一画面内の並置)

**候補の一覧を残したまま、同じ画面の中に原文の該当箇所を出します。**

**理由 — 判断の基準に照らして**

| 事実 | 影響 |
| --- | --- |
| **確かめる対象は1件では終わらない** | **検索の候補は複数返る。1件確かめて戻り、次を確かめる** |
| **乙と丙は、確かめるたびに戻る操作が1回ずつ増える** | **候補5件を確かめると、甲は5操作、乙丙は10操作** |
| **Vasconcelos が示すのは、手間を下げた設計だけが判断を改善すること** | **戻る操作は手間である** |

**基準39 の「追加の操作を求めず」は、乙と丙でも満たせます。** **選択から表示までに操作を挟まないためです。**

**しかし「確かめきる」までの手間は甲が最も小さくなります。** **受入基準を満たすことと、目的を果たすことは別です。**

**狭い画面での扱いは実装工程で定めます。** **並置が成立しない幅では、乙(全面表示)へ落とします。** **これは表示の都合であり、操作列は変わりません。**

## 論点3 — 位置を特定できないときの見え方

**基準38 は、推測した位置を返すことを禁じています。**

### 決定

| 状態 | 見え方 |
| --- | --- |
| 位置が特定できている | **選択可能。選ぶと該当箇所が表示される** |
| **位置が特定できない** | **選択できない状態にする。あわせて、特定できない旨を同じ場所に示す** |

**押せるが何も起きない、という状態を作りません。**

**理由**: **押して何も起きないことは、押して誤った箇所へ行くことと同じ害を持ちます。** **どちらも「確かめた」という感覚だけを与えます。** **Ding et al. は、引用がランダムでも信頼が上がることを示しています。** **確かめられない状態を、確かめられるように見せません。**

**特定できない旨の文言は、基準11 の付記文言表([D-002](https://github.com/Takenori-Kusaka/Filetto/issues/131))と同じ正本から取ります。** **一人称・具体的な表現を用います。**

## 論点4 — 基準40 の記録から、中止条件8 をどう数えるか

**企画書 v4.0 の中止条件8**

> **起案者自身が、印から原文へ飛ぶ操作を1か月で1度も使わなかった場合**、中止する / 観測は公開後1か月

### 決定 — 数える対象と数え方

| 項目 | 値 |
| --- | --- |
| **数える事象** | **基準40 が記録する「基準39 の表示の実行」** |
| **数える単位** | **回数。ただし判定に用いるのは「0回か、1回以上か」だけ** |
| **数える期間** | **直近30日** |
| **数える主体** | **起案者本人の操作のみ**(初版はシングルユーザーであり、区別を要しない) |
| **判定** | **直近30日で0回であれば、中止条件8 に該当する** |

**回数の多寡を目標にしません。** **「使ったか、使わなかったか」だけを見ます。**

**理由**: **回数を目標に置くと、回数を増やす設計へ引かれます。** **本機能の目的は確かめる手間を下げることであって、確かめさせる回数を増やすことではありません。**

**記録に含める項目**(基準40 が定めるもの)

| 項目 | 用途 |
| --- | --- |
| 実行時刻 | **直近30日の切り出し** |
| 対象の安定 ID | **同一ファイルばかりを見ているかの確認**(判定には用いない) |

## 操作列

**論点1〜4 の決定を、利用者の操作の順に並べます。**

| # | 利用者の操作 | システムの応答 | 対応する受入基準 |
| --- | --- | --- | --- |
| 1 | 日本語の自然文で検索する | **候補の一覧を返す。**各候補に安定 ID・ファイル名・パス・**一致した箇所の抜粋** | 基準7 |
| 2 | — | **各候補に、一致した箇所の原文内の位置を含める** | **基準35 / 37** |
| 3 | — | **読み取れなかった / 字形の混入が残った候補に、付記と、その付記が指す箇所の位置を含める** | **基準11 / 36 / 37** |
| 4 | — | **未処理のファイルがある場合、件数・パス・理由の種別を応答へ含める** | 基準10 |
| 5 | — | **位置を特定できない対象は、選択できない状態にし、特定できない旨を示す** | **基準38** |
| **6** | **抜粋または付記を選択する** | **追加の操作を求めずに、同一画面内の並置パネルへ原文の当該箇所を表示する** | **基準39** |
| 7 | — | **実行時刻と対象の安定 ID を監査ログへ記録する** | **基準40** |
| 8 | 別の候補の抜粋または付記を選択する | **6 と同じ。候補の一覧は消えない** | 基準39 |

**利用者の操作は 1・6・8 の3つだけです。** **6 と 8 は同じ操作です。**

**確かめる操作は、候補1件につき1回です。** **戻る操作はありません。**

## MCP 経路

**基準35〜38 が適用されます。** **基準39・40 は適用されません。**

| # | 呼び出し | 応答 |
| --- | --- | --- |
| 1 | 検索 | **候補の一覧。各候補に位置を含む**(基準35 / 37) |
| 2 | — | **付記がある候補には、付記の指す位置も含む**(基準36 / 37) |
| 3 | — | **位置を特定できない場合、その旨を明示する。推測した位置を返さない**(基準38) |

**AI エージェントに対する「1クリック」は意味を持ちません。** **位置を返すところまでが本機能の責務です。**
