### なぜ 1 と 2 を `plan.md` より先に置くか

| 未解決事項 | 解消しないと決まらないこと |
| --- | --- |
| **D-001** | **基準35〜40 のタスク分解。** 何が選択可能な対象で、表示がどこへ出るかが決まらない。**決まらないまま計画すると、画面の設計が実装のついでに決まる** |

## F-002 の計画で最初に確かめること

**F-003 の G-2 再判定(2026-08-14)で、判定者が新しい依存を受け入れました。**

| 項目 | 内容 |
| --- | --- |
| **F-003 前提5** | **抽出の工程が、抽出テキストの各部分と原文内の位置の対応を保持する** |
| **F-002 の現状** | **位置の対応を保持する受入基準が存在しない** |

**これが本計画の最大のリスクです。**

## 期間への影響

**期間・要員・費用は変えません**(6週間 / 1名+AI / 追加支出0円)。**決裁で変えないと決めた事項です。**

**1 と 2 のぶん、実装に使える時間は減ります。** **減った結果、6週間で入る量が想定を下回ると判明した時点で、はじめて範囲の判断になります。** **そのときに SC-P を SC-B へ降格する調整を求めます**([`docs/scope-adjustments.md`](scope-adjustments.md))。**先回りして求めません。**
