## 1. 保証の相手と範囲の方針

| 項目 | 記載 |
| --- | --- |
| 組織として品質を保証する対象 | 顧客向けに公開する Filetto の版(S1 以降)。F-001〜F-003 の受入基準に書いた挙動 |
| 組織として品質を保証しない対象 | S0(企画フェーズ)の探索と検証用の試作。AI(埋め込みモデル・LLM)が返す検索結果・回答そのものの正しさ(本標準の範囲外。Filetto は根拠の位置を示す側で保証する) |
| 検出能力の未測定を許容する期間 | 90日。1名体制では人の層の目隠し測定が成立しないため、人の層は未測定のまま出荷し、その状態を受容する(項目4) |
| 評価の方針 | 停止の申し立て・差し戻し・異議・所見・権限の一時制限の発動の件数を、個人と組織の評価の減点に使わない。AI の利用量・PR の本数・リードタイムを、人の目標値にしない |

## 2. 受容しない条件

- [台帳:個人データ] 個人データの取り扱いに当たる未達
- [台帳:法令] 法令・ライセンスの要求事項に当たる未達
- [台帳:セキュリティ] 利用者のファイルがフォルダの外へ送られうる未達
- [R1未確認] 独立した人の確認を経ていない R1 の変更
- AGPL-3.0 と矛盾するライセンスの依存を含む出荷(印なし。出荷判定者が `license-check` の結果と突合する)
- 受入基準に書いていない挙動を、仕様の変更なしに出荷すること(印なし。出荷判定者が突合する)

## 3. 外枠

| 区分 | 適用されるもの |
| --- | --- |
| 法令 | 個人情報の保護に関する法律(利用者のファイルを外へ送らない設計で、取り扱う側に入らないことを保つ) |
| 契約 | 依存する OSS のライセンス(AGPL-3.0 との整合) |
| 規格・指針 | Unicode UTS #39(紛らわしい文字の扱い)。AI の振る舞いについては適用する指針を定めない(範囲外) |

- 1名体制のため、方針を定めた者と受容する者が同一である。組織として品質を保証すると主張するには、外部の確認者と外部の受容者を置く必要があり、いまは置けない。この受容を、この版で明示する
- 人の層の検出能力は未測定である。1名では目隠しの欠陥注入の「見つける者」が別人にならない。公開後に外部の確認者を得るまで、未測定を受容する
- **社内の受容は、外部への責任を限定しない**
