# ADR-0017: 「確かめる箇所へ1クリック」の受入基準を F-003 へ置く

## ステータス

採用(2026-08-14)

## コンテキスト

2026-08-14 の着手決裁(B案)で、本プロダクトの主訴求が入れ替わった([`docs/decisions/P-001-kickoff-decision.md`](../../docs/decisions/P-001-kickoff-decision.md) 第3章)。

| | 決裁前 | 決裁後 |
| --- | --- | --- |
| 主訴求 | ファイル操作 UI と MCP が同じ実体を共有すること | **手元のフォルダの中だけを見て答え、確かめる箇所へ1クリックで到達すること** |

**決裁は、受入基準の手直しを4件の作業のうちの1つとして確定した**(同 第9章)。**そのうち1件は既存基準の修正ではなく新設である。**

> **新規** / 該当なし → **確認すべき箇所へ1クリックで到達する導線を新設する**
>
> 根拠: **文献が支持しているのは表示ではなく検証コストの低減。表示だけの設計はクリック率1%の側に落ちる**

**新設する基準を、どの機能仕様へ置くかが決まっていなかった。** 本 ADR はそれを決める。

### なぜ置き場所が問題になるか

**機能をまたぐと、通すゲートの数が変わる。**

- **既存の機能へ足す場合**: その機能の G-2 を再判定する
- **新しい機能を立てる場合**: G-2 の対象機能が1つ増え、G-4 の判定記録も1件増える

**決裁は、期間・要員・費用を変えないと明記している**(6週間 / 1名+AI / 追加支出0円。同 第9章「変えないと決めたこと」)。**置き場所の決定は、範囲が広がって見えるかどうかに直結する。**

### 根拠となる研究

**決裁で承認したリスク2件が、この基準の存在理由である**(同 第8章)。

| # | リスク | 出所 |
| --- | --- | --- |
| 1 | **示しても人は確かめない(クリック率1%)** | Chapekis et al., IC2S2 2026 |
| 2 | **過信を減らす設計は、最も嫌われるという研究がある** | Buçinca et al., CHI 2021(N=199) |

**やめる条件8 が、この基準が効いたかどうかを観測する**(同 第8章)。

> **起案者自身が、印から原文へ飛ぶ操作を1か月で1度も使わなかった場合**、中止する

## 検討した選択肢

| 案 | 内容 |
| --- | --- |
| **甲** | **F-003「人と AI が同じ実体を検索する入口」へ受入基準を足す** |
| 乙 | **F-004 として新しい機能仕様を立てる** |
| 丙 | F-001「ファイル操作を可逆にする倉庫」へ足す |

## 決定

**甲を採る。F-003 へ受入基準として足す。**

**価値責任者の判断である(2026-08-14)。**

### 理由

**1. 導線の実体が F-003 の責務の内側にある。**

**新設する基準は「検索の結果から、根拠となった箇所へ到達する」ものである。** F-003 は検索の応答と内容の受け渡しを担っており、**到達先(安定 ID・抜粋・署名付き URL)はすべて F-003 の既存基準が定めている。**

| 依存する既存基準 | 内容 |
| --- | --- |
| 基準7 | 検索の応答に**安定 ID・ファイル名・パス・一致した箇所の抜粋**を含める |
| 基準13・14 | 安定 ID を指定した内容の取得。**本文の直返しと署名付き URL** |
| 基準18 | 原本の実体の取得は署名付き URL を返す |

**`CLAUDE.md`「分割しすぎない」は、新しいインタフェースを追加する変更にその利用箇所を同じ変更へ含めることを求めている。** **導線と到達先を別機能へ割ると、これに反する。**

**2. 手直しする他の2件も F-003 の基準である。**

決裁が確定した手直しの対象は **F-003 基準10** と **F-003 基準11** である(同 第9章)。**新設分を F-003 へ置けば、G-2 の再判定は F-003 の1機能で完結する。**

**3. 範囲を広げていないことが、記録の形で示せる。**

**機能仕様を増やさないため、G-2 の対象機能は3件のままである。** 期間・要員・費用を変えないという決裁の内容と、記録が一致する。

## 採らなかった選択肢とその理由

### 乙 — F-004 として新しい機能仕様を立てる

**主訴求へ昇格した要素であり、独立した機能仕様として立てるほうが記録としては素直である。** 「何が主訴求か」を機能仕様の一覧から読み取れるという利点がある。

**採らなかった理由は3つある。**

| # | 理由 |
| --- | --- |
| 1 | **到達先の基準がすべて F-003 にあり、F-004 は F-003 へ全面的に依存する。** 単独で意味を持つ変更にならない |
| 2 | **G-2 の対象機能が3件から4件へ増える。** 決裁が「変えない」と明記した範囲に対し、記録上は拡大に見える |
| 3 | **F-002 / F-003 の `plan.md` が未作成の段階で、判定対象を1件増やす。** G-4([#81](https://github.com/Takenori-Kusaka/Filetto/issues/81))の未判定分が2件から3件になる |

**主訴求であることは、機能仕様の分割ではなく決裁の正本が記録する。** **機能の粒度は責務で決め、重要度で決めない。**

### 丙 — F-001 へ足す

**採らない。** F-001 は破壊的操作の可逆性を担う機能であり、**検索結果からの到達とは責務が異なる。** F-001 の受入基準22件はいずれも削除・復元・バージョン保管に関するものであり、**検索の応答を扱う基準を1件も持たない。**

**F-001 は G-4 を通過済みである**([`docs/gates/g4-F-001-2026-08-13.md`](../../docs/gates/g4-F-001-2026-08-13.md))。**ここへ基準を足すと、通過済みの G-4 も再判定になる。**

## 影響

| 対象 | 影響 |
| --- | --- |
| `specs/F-003/spec.md` | **受入基準を新設する。基準10・11 も手直しする**(決裁 第9章) |
| **G-2 要件合意** | **F-003 を対象に再判定する。** 受入基準の内容の変更であるため([`docs/gates/g4-F-001-2026-08-13.md`](../../docs/gates/g4-F-001-2026-08-13.md)「判定に持ち込まないもの」) |
| `specs/F-001` / `specs/F-002` | **変更しない。** G-2 の再判定の対象外 |
| G-4([#81](https://github.com/Takenori-Kusaka/Filetto/issues/81)) | **未判定は F-002 / F-003 の2件のまま。増えない** |
| やめる条件8 | **観測対象が確定する。** 「印から原文へ飛ぶ操作」は F-003 の新設基準が定める操作を指す |

**基準の番号は、既存の番号を振り直さずに追加する**(`specs/F-003/spec.md` の既定)。

## 確かめられていないこと

**1クリック導線が実際に使われるかは、実装して運用するまで分からない。**

**Chapekis et al. のクリック率1%は、検索エンジンの引用リンクに対する測定である。** **本プロダクトの利用者(起案者本人。エンジニア)と同一の母集団ではない。** **この数値をそのまま本プロダクトへ当てはめる根拠はない。**

**やめる条件8 は、この不確かさを観測するために置いたものである。** 本 ADR は置き場所を決めるだけであり、**効果を主張しない。**
