# ADR-0016: 変更規模の数値を目標の目安とし、合否の条件にしない

## ステータス

採用(2026-08-13)

## コンテキスト

2026-08-13 の G-4(F-001)判定で、価値責任者が判定基準2(タスク分解の粒度)に条件を付けた。

> **目標目安として定義し、制限事項にしないという条件付き。もし条件をのめないなら制限を外す。**

**判定は通過している。** 条件は、通過の効力に付随するものである([`docs/gates/g4-F-001-2026-08-13.md`](../../docs/gates/g4-F-001-2026-08-13.md))。

### 条件と現行の記述が矛盾している

`CLAUDE.md`「タスクの粒度」は次のとおりである。

```
| 項目 | 目安 | 上限 |
| 変更行数 | 100行 | 400行 |
| 変更ファイル数 | 10未満 | 15 |
| レビュー所要時間 | — | 30分で読み切れること |

1つの変更に複数の関心事を混ぜません。上限を超える場合は実装計画へ差し戻します。
```

**「上限」「超える場合は差し戻します」は制限事項の書き方である。** 条件と両立しない。

### 現行の記述は、自分で自分の根拠を否定している

**同じ文書に次が書かれている。**

> **上限400行は 2006年の調査**(2,500件のレビュー・320万行)**に由来します。原典が測ったのはレビューの継続時間と欠陥検出率の関係であり、行数上限そのものを検証した測定ではありません。**(中略)**2010年代以降に独立して再検証した研究は確認されていません**(標準本文の暫定マーク EV-0005 / 根拠の水準 E1 / 見直し 2027-08)。
>
> ファイル数(10 / 15)には**数値自体の実証がありません**。**区切り位置は自組織で較正する対象です。**

**根拠の水準が E1(最も弱い)であり、ファイル数に至っては実証が無い数値を、合否の条件として運用していた。**

**条件は、記述をその根拠の水準へ合わせるものである。**

### 機械では、既に制限になっていない

**実測した。**

```
$ grep -rn "maxChangedLines\|maxChangedFiles" process.config.json scripts/gate/ .github/workflows/

process.config.json:153  "maxChangedLines": 400
process.config.json:154  "maxChangedFiles": 15
```

**`process.config.json` に値はあるが、これを読んで合否を決める検査は1件も無い。** ゲートのスクリプトにもワークフローにも参照が無い。

**つまり制限として働いていたのは文書の記述だけであり、機械では最初から目安だった。**

## 決定

### 1. 「上限」を「目標」と書き換える

**`CLAUDE.md`「タスクの粒度」の表から「上限」の語を外す。**

| 項目 | 目標 | 大きいと判断する目安 |
| --- | --- | --- |
| 変更行数 | 100行 | 400行 |
| 変更ファイル数 | 10未満 | 15 |
| レビュー所要時間 | — | **30分で読み切れること** |

**「超える場合は実装計画へ差し戻します」を削る。**

### 2. 差し戻しの根拠を「読み切れないこと」に一本化する

**数値を超えたことは、差し戻しの理由にしない。**

**差し戻しの理由は「30分で読み切れないこと」だけとする。**

**理由**: **レビュー所要時間は、2006年の調査が実際に測った量である。** 行数は、そこから導いた代理指標にすぎない。**代理指標より、測った量そのものを条件にするほうが根拠が強い。**

**数値を超えた変更は、読み切れるかどうかを確かめる合図として扱う。** 超えたこと自体は不合格ではない。

### 3. 数値を超えた場合、記録を残す

**超えたこと自体は不合格ではないが、記録は残す。**

| # | 記録するもの |
| --- | --- |
| 1 | 実際の変更行数・ファイル数 |
| 2 | **レビューに要した時間** |
| 3 | 読み切れたかどうか |

**理由**: `CLAUDE.md` は「運用開始後は自組織の実測へ置き換えます」と定めている。**置き換えるための実測が、超えた事例からしか得られない。** 数値で止めていると、**上限より大きい変更の所要時間が永久に採れない。**

**制限を外すことは、較正のためのデータを採れるようにすることでもある。**

### 4. 機械で強制しない

**`process.config.json` の `maxChangedLines` / `maxChangedFiles` を読んで合否を決める検査を追加しない。**

**現状そうなっており、変更しない。**

**キー名は `max*` のままとする。** テンプレート(`pit-in-template`)が定めた構造であり、**本案件が改名すると、テンプレート由来の他の装置との対応が壊れる。** **値の意味は本 ADR と `CLAUDE.md` が定める。**

### 5. `selfHealMaxIterations` は対象外

**自己修正ループの反復回数の上限(3回)は、本 ADR の対象に含めない。**

**理由**: **これは規模の指標ではなく、停止条件である。** `CLAUDE.md` は「同じ失敗を3回繰り返す場合、原因は実装ではなく受入基準の不備であることが多い」と定めており、**上限に達したら人が受入基準へ戻る**という設計である。**目安に変えると、停止しない経路が生まれる。**

## 採らなかった選択肢

### 案A: 現状のまま(上限として運用する)

**採らなかった理由**: **判定者が条件として明示した。** 「条件をのめないなら制限を外す」とあり、**現状維持は選択肢に含まれていない。**

**加えて、根拠の水準(E1・ファイル数は実証なし)が合否条件を支えない。**

### 案B: 数値を完全に削る

**「もし条件をのめないなら制限を外す」の後段に沿う案である。**

**採らなかった理由**: **条件の前段(目標目安として定義する)が先に来ている。** 後段は前段をのめない場合の代替であり、**前段をのめる以上、後段を採る理由がない。**

**加えて、数値が無いと決定3 の記録が採れない。** 「超えた事例」を識別できないため、較正のためのデータが集まらない。

### 案C: 数値を上げる(例: 800行)

**採らなかった理由**: **上げる根拠が無い。** 400行に根拠が無いのと同じ理由で、800行にも根拠が無い。**根拠の無い数値を別の根拠の無い数値へ置き換えても、何も改善しない。**

**問題は数値の水準ではなく、根拠の弱い数値を合否条件にしていたことである。**

### 案D: レビュー所要時間を機械で測って合否にする

**採らなかった理由**: **標準 5.7.4 が「記述の実質性を機械的に判定して、承認の可否を自動的に決めてはならない」と定めている。** 所要時間は読み切れたかどうかの代理でしかなく、**速く閉じたことが読めたことを意味しない。**

**加えて、機械が時間で止める構成は、判定者に「時間内に終える」誘因を与える。** 判定の質を下げる方向へ働く。

## 帰結

### 受け入れるもの

| # | リスク |
| --- | --- |
| 1 | **大きい変更が実装計画の差し戻しなしに進みうる** |
| 2 | **G-6(独立レビュー)が未達である間、粒度が品質そのものになるという前提が弱まる** |

**2 が重い。** `context/projects/P-001.md` 運用上の注意7 は次のとおりである。

> **G-6 が未達である以上、タスクの粒度が品質そのものになる。** 1タスク100行目安・上限400行・変更ファイル15以内を機械的に守る

**この記述は本 ADR と矛盾する。決定1 に合わせて書き換える。**

**弱まる分は、決定2 の「30分で読み切れること」が受ける。** これは機械では判定できず、**判定者の判断に依存する。**

### 得られるもの

| # | 内容 |
| --- | --- |
| 1 | **較正のためのデータが採れる**(決定3) |
| 2 | 根拠の水準と記述の強さが一致する |
| 3 | **意味のある単位で分けられる。** 数値に合わせて意味を成さないほど切り刻む誘因が消える |

**3 は `CLAUDE.md`「分割しすぎない」と同じ方向である。** 数値の上限と「分割しすぎない」は、もともと互いに引っ張り合っていた。

### 影響する記録

| 場所 | 直すもの |
| --- | --- |
| `CLAUDE.md`「タスクの粒度」 | **上限 → 目標。差し戻しの記述を削る** |
| `context/projects/P-001.md` 運用上の注意7 | **「機械的に守る」を直す** |
| [ADR-0012](0012-line-limit-scope.md) | **置き換えない。** 適用範囲(何を数えるか)を定めたものであり、本 ADR は強さ(合否か目安か)を定める。**論点が違う** |
| `specs/F-001/plan.md` | **直さない。** 「上限を超えた時点で本計画へ差し戻します」と書いているが、**Task-8 の2分割の条件として自ら課したものであり、規約の適用ではない** |
