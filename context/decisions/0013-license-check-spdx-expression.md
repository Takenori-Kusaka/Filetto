## コンテキスト

### ADR-0007 が置いた暫定と、その前提

ADR-0007 は `process.config.json` の `ci.allowedLicenses` へ **classifier 表記6件**を追加しました。

```
MIT License / Apache Software License / BSD License / Apache-2.0 OR BSD-2-Clause /
Mozilla Public License 2.0 (MPL 2.0) / Python Software Foundation License
```

ADR-0007 は自らこれを **「汚い回避策」** と記し、**[pit-in-template#13](https://github.com/Takenori-Kusaka/pit-in-template/issues/13) の修正後に削除する**という期限を置きました。

### 起票時の見立てと、実測との差(PL-0001 §1)

[#60](https://github.com/Takenori-Kusaka/Filetto/issues/60) は「PyJWT と `cryptography` が PEP 639 移行で classifier を削除したため、classifier のみを読む検査系では `UNKNOWN` になる」という前提で起票されました。

**この前提のうち1つは実測と異なりました。**

| 起票時の前提 | 実測 |
| --- | --- |
| PyJWT / cryptography は classifier を削除済み | **そのとおり**(`License-Classifier: UNKNOWN`) |
| classifier のみを読む検査系では `UNKNOWN` 判定になる | **`pip-licenses` 5.5.5 は `License-Expression` を先に読むため `UNKNOWN` になりません。** `--from=classifier` を明示しても `MIT` を返します |
| 表記を吸収する回避策では拾えない | **そのとおり。ただし理由が別です** |

**本当の原因は `--allow-only` の照合方法でした。**

```
license Apache-2.0 OR BSD-3-Clause not in allow-only licenses was found for package cryptography:50.0.0
```

`cryptography` の `Apache-2.0 OR BSD-3-Clause` を**1つの文字列として**許可一覧と比較するため、**`Apache-2.0` も `BSD-3-Clause` も一覧にあるのに落ちます。**

ADR-0007 が一覧へ `Apache-2.0 OR BSD-2-Clause` という文字列を入れているのは、`packaging` で同じ問題を踏んだ痕跡です。**式の組み合わせは無限にあり、文字列の列挙では追いつきません。**

**#60 の「暫定回避策を延命するのではなく読む場所を変えるべき」という方向は正しく、変えるべきは読む場所ではなく照合の仕方でした。**

### `--partial-match` は使えません(PL-0001 §2.3)

`--partial-match` を付けると `cryptography` は通りますが、**許可していない `MIT-0`(cffi)も同時に通ります**(実測)。

## 決定

**決定1〜3 は価値責任者が [#60](https://github.com/Takenori-Kusaka/Filetto/issues/60) で下したものです。**

### 1. `process.config.json` から「表記の吸収」6件を削除する

**削除の理由を取り違えないこと。**

| 誤った理解 | 正しい理解 |
| --- | --- |
| 表記の揺れが解消したから削除できる | **式として評価するようになったから、文字列の列挙が不要になった** |

**`Apache Software License` が Apache-2.0 以外を指しうるという曖昧さは残ります。** ADR-0007 §非機能への影響に書かれたとおりです。

**変わるのは「黙って通るか、出力に現れるか」だけです。**

| | ADR-0007 の状態 | 本 ADR の後 |
| --- | --- | --- |
| 曖昧な分類子の所在 | `process.config.json` の許可一覧 | `scripts/gate/license-check.mjs` の補正表 |
| 通ったときの記録 | **残らない** | **通るたびに「※複数の SPDX を含みうる」と出力へ残る** |

### 2. `PIT_IN_SELF_PACKAGES` を有効化せず、空のままにする

**入口だけ用意して空にしてある状態を維持します。**

理由は2つです。

| # | 理由 |
| --- | --- |
| 1 | **検査範囲を狭める変更であり、いま必要ではない。** `AGPL-3.0-or-later`(`filetto` 自身)が検査対象に入っていても実害が出ていない。**実害が出ていない段階で検査範囲を狭めると、狭めたこと自体が忘れられる。** 本案件には `secretScan` が空のまま通過し続けた前例がある |
| 2 | **必要になったときに有効化できる状態が、いま最も良い状態である** |

**有効化が必要になる条件を記録します。**

- **`filetto` 自身のライセンスを AGPL 以外へ変える場合**
- **依存に自プロジェクトのパッケージを含める場合**

### 3. ADR-0007 を書き換えず、本 ADR で暫定部分を置き換える

| やること | やらないこと |
| --- | --- |
| **本 ADR を書き、ADR-0007 の暫定部分を置き換える** | ADR-0007 の本文を書き換える |
| **ADR-0007 のステータスへ置き換えの範囲を1行追記する** | ステータス以外を触る |

**ADR-0008 が ADR-0003 の決定5 を置き換えたときと同じ形です。**

### 4. ADR-0007 の「期限」節は、pit-in-template#13 を待たずに解消する

ADR-0007 は「#13 が修正され、正規化された照合が入った時点で、表記の吸収として追加した項目をすべて削除します」としていました。

**本 ADR は #13 を待たずに、このリポジトリ側で判定を持つことで解消します。**

**ただし、上流の修正を不要にするものではありません。** pit-in-template#13 の起票内容(`pip-licenses` 側での正規化)は引き続き有効です。**本 ADR はテンプレートから生成した1リポジトリの選択であり、テンプレート側の設計の代替ではありません。**

### 5. この ADR が決めないこと

- **`scripts/gate/license-check.mjs` の実装そのもの**。[PR #65](https://github.com/Takenori-Kusaka/Filetto/pull/65)(Platform)の対象
- **`adapters/python.json` の検査コマンドの変更**。同上
- **`node` アダプタの `license-checker-rseidelsohn`** に同種の問題があるか。ADR-0007「この決定で解決しないこと」のまま未確認
- **許可ライセンスの一覧そのもの**(SPDX 8件)。ADR-0007 の恒久部分であり、本 ADR は置き換えない

## 影響

**この決定によって得られるもの:**

- **SPDX 複合式(`Apache-2.0 OR BSD-3-Clause`)を、文字列の追加なしに正しく判定できる**
- **補正して通したものが証跡に残る。** ADR-0007 では黙って通っていた
- ADR-0007 の暫定部分が、pit-in-template#13 を待たずに解消する

**トレードオフ:**

- **判定の装置をこのリポジトリが持つ。** テンプレートから生成したリポジトリが、テンプレート側の検査コマンドを独自に置き換える構図になる。**ADR-0007 が「避ける」とした構図に、実測を根拠として踏み込む**
- **強制層のファイルが1つ増える**(`scripts/gate/license-check.mjs`)。この装置自体の正しさを担保するテストが要る
- **曖昧さは消えない。置き場所が変わるだけである**

**この決定で解決しないこと:**

- **`pip-licenses` 側の正規化**(pit-in-template#13)。**上流の修正は引き続き必要**
- **`node` アダプタの検査経路**。ADR-0007 のまま未確認
- **`Apache Software License` が実体として何を指すか**。補正表で SPDX へ寄せるが、**分類子そのものの曖昧さは解消しない**
