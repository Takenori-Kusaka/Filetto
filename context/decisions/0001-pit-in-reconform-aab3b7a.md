# ADR-0001: ピットイン方式のテンプレートを aab3b7a へ再準拠する

## ステータス

採用(2026-10-08)。Spec: setup。起案は AI の担い手(Claude Sonnet 5.5)、採否は Takenori Kusaka(利用者がセッション内で代理記入を指示)。

## コンテキスト

Filetto は 2026-08-12 の旧テンプレート(P-001)で初期化された。process-compass から、改訂後のテンプレート pit-in-template aab3b7a への再準拠の依頼を受けた(席と担い手、組織としての品質保証、コマンドで回る運用)。テンプレートは自動では追従しない。過去の判定記録と ADR は書き換えない。旧様式に欄が無かった記録は埋め戻さず「未達」として残す。

## 決定

次を取り込む。時期は 2026-10-08(依頼から2週間以内)。

- `.claude/`、`.github/`(workflows・rulesets・PR 様式)、`scripts/`、`templates/`、`adapters/`、`AGENTS.md`、`CLAUDE.md`、`docs/README.md` を aab3b7a で置き換える。Filetto 独自のゲート・スクリプト・ワークフロー(license-check、external-host-check、record-integrity、pr-base-check、merged-reachability、investment-measure ほか)は、置き換えにより廃止する
- ロール別スキル(po・dev・qm・audit・platform)と Label Mailbox 連携を廃止する。1名で5ロールを回す形が形骸化していたため
- 構成を `/process-change` で再生成する。人数は1名、外部の確認者なし、全席の責任者は同一人物(兼務は逸脱として表示される)。AI の担い手は開発者の席で宣言し、運用形態は協働とする。委任は登録しない(層1 は委任を認める余地を残すが、規則は未登録)
- 層1(`docs/quality-assurance-policy.md`)を置く。1名体制のため、人の層の検出能力は未測定とし、その受容を層1 に書く
- D-0 と企画書を最新様式へ移す。旧 D-0 v1.4 の本文は付録として保存する
- 旧 CLAUDE.md の手書きの規則は `context/standards/legacy-claude-md-2026-08.md` へ退避する

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 独自ゲート・スクリプトを残して差分だけ取り込む | 利用者が「置き換える」を選んだ。独自資産は強制層の縮小・拡大が混在し、テンプレートとの差分を追い続ける負担が残る |
| ロール別スキルを残す | 利用者が「廃止」を選んだ。指摘 #248〜#275 の「1名で5ロール」の形骸化に当たる |
| 事業ステージを PoC へ戻す | 2026-10-11 に Takenori Kusaka が判定し、MVP のまま戻さないと決めた。戻すには SG の判定記録が要るが、SG の判定の値に「戻す」が無く、既存の `sg0-P-001-2026-08-12.md` は通過の記録で根拠にならなかった(標準チームへの申し入れ: `docs/process-compass-requests/2026-10-11-staged-introduction.md`) |
| 再準拠せず旧構成を続ける | 依頼の期限内に取り込む方針。旧構成では G-6 の未達や組織継続の表示が出ない |

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | 変えられる(同一ブランチの履歴で復元できる) |
| 変えるとしたら必要なこと | 独自ゲートを戻す場合は旧 main の `scripts/gate/` から取り込む。強制層の縮小に当たるため、`state:needs-platform` を経由する |
| いつまでなら安く変えられるか | マージ前 |

## 未達・未決として残すもの

- 席の責任者本人の力量の確認(価値責任者・技術判断者・独立レビュア・出荷判定者): 本人以外の確認者がいないため未確認
- 事業ステージ: MVP のまま(2026-10-11 に判定済み)
- 旧 `investment-measure` の再設置(企画書の継続測定)
- 強制層の遮断: 生成器が MVP 向けに有効化したが、2026-10-11 に Takenori Kusaka の承認で緩和した(`guard.enabled: false`、見直し 2027-01-08。ADR-0015 の維持)
- ブランチ保護(`gh api` による ruleset 適用)は、マージ後に実行する。マージ前に必須チェックを要求すると、main にまだ無いチェックでマージが止まるため
