# ADR-0009: 行数上限を判断記録・機能仕様・設計文書へ適用しない

## ステータス

**判定者の記入待ち(2026-08-13)**

決定そのものは価値責任者が下している([PR #39](https://github.com/Takenori-Kusaka/Filetto/pull/39) への判断)。**「検討した選択肢」の理由欄は、判定者が記入する。** 標準 第5章 5.7.3 は「どの案を選ぶかの理由は、人間が記入しなければならない。**この記入を AI に生成させてはならない**」と定めている。記入が済むまで採用としない。

## コンテキスト

`CLAUDE.md` はタスクの粒度として **変更行数の上限400行**を定めている。2026-08-13、[ADR-0002(対外インターフェース契約)](./0002-external-interface-contract.md)が **351行**となり、Dev がこれを上限超過として実装計画へ差し戻すべきか判別できなかった。

当時の `CLAUDE.md` には「上限400行」とだけ書かれており、**何を数えるのか、何を除外するのか、この数値がどこから来たのか**が読み取れなかった。

### 標準本文から落ちていた情報

`CLAUDE.md` は標準([第4章 変更単位の水準](https://takenori-kusaka.github.io/process-compass/phase4-process-design/gate-criteria/))から数値のみを転記しており、標準が併記している次が落ちていた。

| 落ちていた情報 | 標準本文の記述 |
| --- | --- |
| 適用の前提 | **逐行読解しか手段がない場合の既定値** |
| 除外規定 | 自動生成ファイル・ロックファイル・一括整形は算定から除外 |
| 上限が成立しない類型 | 機械的変換(決定論的 / テストで検出可能 / 部分的に取り消せる)の3条件 |
| 暫定であること | 暫定 EV-0005 / 見直し 2027-08 / 根拠の水準 E1(間接) |
| 根拠の限界 | **レビューの継続時間に関する調査からの導出であり、行数上限を直接検証した測定ではない** |
| 成立の前提 | 2006年当時のC系プロダクトコードとツール支援レビュー。2010年代以降の再検証は確認されていない |
| 較正の手続 | 運用開始後は自組織の実測へ置き換える(第85パーセンタイル / 四半期 / **自動化してはならない**) |

**数値だけが転記され、その数値が何を守ろうとしているかが落ちていた。**

### 判別できない制約は守られない

**「上限400行」だけを読んだ Dev は、351行の ADR を差し戻すべきか判別できなかった。** 判別できない制約は、守られないか、過剰に守られるかのどちらかになる。

**同じ判断は、本リポジトリで作業する他のロールでも繰り返し発生する。**

## 決定

### 1. 行数上限を判断記録(ADR)・機能仕様・設計文書へ適用しない

**代わりにレビュー所要時間(30分で読み切れること)で判定する。**

### 2. 数える対象と除外を明記する

| 項目 | 内容 |
| --- | --- |
| 数える対象 | **実装コードの差分** |
| 除外 | 自動生成ファイル・ロックファイル・一括整形 |
| 除外 | 機械的な変換。ただし「決定論的である」「テストで正しさを検出できる」「部分的に取り消せる」の3点を満たすものに限る |

### 3. 数値が暫定であることと、その根拠の限界を `CLAUDE.md` へ書く

**上限400行は 2006年の調査に由来し、原典が測ったのはレビューの継続時間と欠陥検出率の関係である。** 行数上限そのものを検証した測定ではない。ファイル数(10 / 15)には数値自体の実証がない。

**区切り位置は自組織で較正する対象である。**

### 4. `process.config.json` との差を期限つきで許容する

`process.config.json` の `maxChangedLines: 400` は変更しない。**同ファイルは強制層でありエージェントから書けない。**

| 項目 | 内容 |
| --- | --- |
| 当面 | **差を許容する。** 現時点で実害は出ていない(ADR-0002 は351行で400を下回る) |
| 実害の定義 | **ADR または機能仕様が行数超過で CI に落ちること** |
| 期限 | **実害が出た時点、または D-0 の次回レビュー期日(2026-11-12)のいずれか早い方** |
| 記録 | 技術負債台帳へ載せる |

**「後で直す」を期限なしで残さない。** 本案件には `adapters/python.json` の `secretScan` が空のまま `secret-scan` が通過し続けている前例がある。

## 検討した選択肢

**理由欄は判定者が記入する。** 標準 5.7.3 により、この記入を AI が生成してはならない。

| 案 | 採らなかった理由 |
| --- | --- |
| **A. ADR にも行数上限を適用し、超過したら分割する** | **要記入。** 参考: `context/decisions/README.md` は「採らなかった選択肢を書き残すことは、後任者が同じ検討を繰り返さないための唯一の手段」としている。ADR-0002 は単一の関心事(対外インターフェース契約)を扱う1ファイルであり、行数の大半を「採らなかった選択肢とその理由」が占める |
| **B. ADR にも適用し、超過したら記述を削る** | **要記入。** 参考: 決定そのものは削れないため、削る対象は検討した選択肢の記録になる |
| **C. 上限の数値そのものを引き上げる** | **要記入。** 参考: 標準は上限400行を暫定(EV-0005 / 根拠の水準 E1)とし、較正は自組織の実測(第85パーセンタイル / 四半期)によるとしている。本案件は実装を伴う初めての案件であり、較正に足る実測を持たない |
| **D. 判断記録・機能仕様・設計文書へ適用しない(採用)** | — |

### 標準本文に根拠を持たないこと

**「ADR に行数上限を適用しない」は標準本文に根拠を持たない。** 標準は設計文書のサイズ基準を規定していない。**本リポジトリの判断として記録する。**

**上流へ論点として返している**: [pit-in-template#16](https://github.com/Takenori-Kusaka/pit-in-template/issues/16)。標準側で規定が設けられた場合、**本 ADR の決定1 は差し替えの対象になる。**

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | **変えられる** |
| 変えるとしたら必要なこと | `CLAUDE.md` の該当節を書き換える。**既に作成した ADR・機能仕様を遡って分割する必要はない**(適用範囲の変更であり、成果物の要件ではないため) |
| いつまでなら安く変えられるか | **いつでも。** ただし ADR の本数が増えるほど、「適用する」へ戻したときの分割対象が増える |

## 影響

**この決定によって得られるもの:**

- **Dev が ADR の行数超過を判別できるようになる。** 判別できない制約が残らない
- ADR の「採らなかった選択肢とその理由」が、行数を理由に削られない
- **数値が暫定であることが、制約を読む側に見える**

**トレードオフ:**

- **`CLAUDE.md` が長くなる。** 全ロールが毎回読む文書である
- **`process.config.json` との差が残る。** 設定を機械可読の正本とする設計に対して、文書が異なることを述べる状態になる。期限つきで許容する(決定4)
- **標準本文に根拠を持たない判断を1件抱える。** 標準側で規定が設けられた場合、差し替えの対象になる

**この決定で解決しないこと:**

- **`process.config.json` の `maxChangedLines` は変わらない。** 強制層であり、Owner の操作を要する
- **区切り位置の較正は行っていない。** 実測(第85パーセンタイル / 四半期)を持たない。**較正は自動化してはならない**(標準)
- **「30分で読み切れること」の判定方法は定めていない。** 判定者の判断による
