# ADR-0008: VersionStore の実装に Lore を採用し、自前 CAS を採らない

## ステータス

採用(2026-08-12)

**本 ADR は [ADR-0003](./0003-reversible-file-operations.md) の決定5(バージョン保管はインターフェースの背後に置く)のうち、初版実装を「自前の軽量 CAS」とした部分を置き換える。** ADR-0003 のそれ以外の決定(破壊的操作の可逆性、ゴミ箱、保持期間、通知の層、`VersionStore` 境界を置くこと)は有効なまま維持する。

## コンテキスト

ADR-0003 は `VersionStore` の初版実装を**自前の軽量 CAS**と定めた。理由は「外部 OSS への依存を初版では持たない」であり、Lore については「2026-08 時点で v0.8 台のプレ 1.0 段階であり、エコシステムが未成熟」として採らなかった。同 ADR は同時に、**価値責任者の判断で再評価を前倒しし、[#4](https://github.com/Takenori-Kusaka/Filetto/issues/4) で検証して有用と認められれば v1.0 未達でも初版から採用する**と記していた。

[S0-005](../../docs/spikes/S0-005-lore.md) がその検証である。基準1〜5 をすべて満たしたうえで、**前提にあった「ライブラリとして組み込める」は成立しない**(`loreserver` の常駐が必要)ことが判明し、判断が価値責任者へ差し戻されていた。

| # | 基準 | 判定 |
| --- | --- | --- |
| 1 | SDK から 登録・取得・履歴一覧・バージョン削除の4操作 | 満たす(`@lore-vcs/sdk` で4操作すべて成功) |
| 2 | 追加コンテナ 1 個以下、またはライブラリ組み込み | 満たす(公式 Dockerfile で1コンテナ。**ライブラリ単体では不可**) |
| 3 | 10MB PDF の末尾を変えた10版が単純加算の 30% 以下 | 満たす(**9.6%**) |
| 4 | 破損時に沈黙して誤ったデータを返さない | 満たす |
| 5 | 破壊的変更の予告または保管形式の互換性に関する記述 | 記述あり |

ライセンスは本体・JS SDK・Go SDK いずれも **MIT**。検証時点のバージョンは `lore 0.8.6+373`。

## 決定

### 1. `VersionStore` の実装として Lore を採用する

自前 CAS は実装しない。

### 2. `loreserver` の常駐を受け入れる

`docker compose` にコンテナを1個追加する。**`docker compose up` 一発という前提は維持される**(利用者の操作は増えない)。コンテナ数の最小化という目標は、この1個ぶん後退する。

### 3. 保管パスを明示設定する

Lore の既定の保管先は一時ディレクトリであり、**放置すると消える**。保管パスは環境変数で明示的に指定し、既定値に依存しない。設定化の方針は ADR-0003 の決定4(保持期間を定数化しない)と同じ扱いにする。

### 4. 保管領域の定期検証と `.~loretemp` の掃除を Filetto 側で持つ

**Lore に修復コマンドが存在しない。** 破損検出は Lore が行うが、検出後の回復手段は提供されない。したがって次を Filetto の責務とする。

- 保管領域の定期検証(破損の早期発見)
- `.~loretemp` の掃除

掃除を利用者の手作業に委ねない(設計標準 [[calm-technology]]「利用者に管理タスクを暗黙に課さない」)。

### 5. `VersionStore` 境界の背後に置く

ADR-0003 の決定5 で定めた `VersionStore` インターフェースは維持する。Lore の API は **0.x の間、非互換に変わりうる**。Lore の型・イベント・エラーを Filetto の他の層へ漏らさない。

## 検討した選択肢

理由欄は価値責任者(takenori-kusaka)が記入した(2026-08-12)。

| 案 | 採らなかった理由 |
| --- | --- |
| **自前 CAS を維持する**(ADR-0003 の当初決定) | **あり得ない。履歴管理を独自実装することは技術負債にしかならない。最優先事項とした「部品としての将来的な拡張性」の観点で強く否定される案である。** |
| **Lore を採用する(採用)** | — |

**この判断は、S0-005 が提示した条件1(`loreserver` の常駐を受け入れるか)への回答でもある。** S0-005 は「条件1 を受け入れない場合、ADR-0003 の自前 CAS を維持し、再評価の条件を『サーバ常駐なしのローカル専用モードが提供されたとき』へ書き換える」という分岐を示していた。**受け入れる側を採ったため、この分岐は発生しない。**

ADR-0003 の「バージョン管理の実現方式について」で検討した Git / Git LFS / git-annex / Subversion / Clustta / DVC / lakeFS / SeedDMS / LogicalDOC / ストレージ層の機能は、いずれも本 ADR で再検討していない。**採らない理由は ADR-0003 の記録がそのまま有効である。**

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | **変えられる** |
| 変えるとしたら必要なこと | `VersionStore` インターフェースの実装を差し替える。**境界を置いていることが、この決定を安く保つ唯一の条件である**(決定5)。加えて `docker compose` から `loreserver` を外し、既存の保管領域から新しい実装へデータを移す経路が要る |
| いつまでなら安く変えられるか | **保管データが積み上がる前まで**。実装差し替えのコストは境界のおかげで一定だが、データ移行のコストは保管量に比例して増える。実装着手から初回リリースまでの間が最も安い |

**自前 CAS との差はここにある。** 自前実装は「差し替える先」を持たず、保守を降ろす相手もいない。外部実装は境界さえ守れば降ろせる。

## 非機能への影響

| 項目 | 影響 |
| --- | --- |
| 性能 | FastCDC によるチャンク単位の重複排除により、**10MB PDF の10版で単純加算の 9.6%**(S0-005 基準3)。自前 CAS のファイル単位ハッシュでは同一内容の完全重複しか排除できず、末尾だけ変えた版は毎回まるごと保管される。**ディスク消費で有利** |
| 可用性 | **`loreserver` が単一障害点になる。** これが常駐を受け入れたことの代償である。サーバが落ちるとバージョン保管の全操作が失敗する。Filetto 本体の検索・閲覧は継続できる設計にする |
| セキュリティ | `loreserver` はコンテナ内に閉じ、ホストへ公開しない。ゴミ箱内のアクセス制御(ADR-0003)は Filetto 側で行い、Lore へ委譲しない |
| 運用 | **保管パスの明示設定(決定3)を怠ると、データが一時ディレクトリごと消える。** 設定漏れを起動時に検出して失敗させる。`.~loretemp` の掃除と定期検証(決定4)が運用の追加項目になる |

## 事業への影響

| 項目 | 内容 |
| --- | --- |
| 顕在化が分かる兆候 | Lore の 0.x が非互換に変わり、`VersionStore` の実装が追随できなくなること。または `loreserver` の障害でバージョン操作が失敗する報告が出ること。または Lore の開発が停止すること(2026-08-11 時点で最終更新は同日、8,375 stars) |
| 回復に要する時間 | **5日**(`VersionStore` 境界の背後で別実装へ差し替える工数。データ移行を含まない) |
| 影響を受ける利用者・業務 | バージョン履歴を実際に使う利用者。閲覧・検索のみの利用者は影響を受けない |

## 影響

**この決定によって得られるもの:**

- **履歴管理の実装と保守を自前で持たない。** これが本決定の主目的である
- チャンク単位の重複排除・Merkle ツリー・破損検出を、実装せずに得る
- **部品としての差し替え可能性が残る。** 自前実装は差し替え先を持たないが、外部実装は境界さえ守れば降ろせる

**トレードオフ:**

- **`docker compose` のコンテナが1個増える。** コンテナ数の最小化という目標は後退する
- **`loreserver` が単一障害点になる。** 常駐を受け入れた代償である
- **プレ 1.0 の依存を初版から抱える。** ADR-0003 が当初これを採らなかった理由は消えていない。**消えていないまま、拡張性の観点がそれを上回ると判断した**
- **修復コマンドが無い。** 破損時の回復手段を Filetto 側で持つ必要がある(決定4)

**この決定で解決しないこと:**

- **`VersionStore` インターフェースの具体的なシグネチャ**は本 ADR の対象外。G-3 で決める(`context/projects/P-001.md` 未決の論点2)
- **保管領域の定期検証の実装方式**(頻度・検証範囲・失敗時の通知の層)は対象外。実装着手時に定める
- **Lore が 1.0 に到達したときの扱い**は対象外。到達時点で本 ADR を再評価する
- **バージョン間の差分表示・同時編集の排他制御・バージョンの分岐**は、ADR-0003 と同じく対象外のまま
