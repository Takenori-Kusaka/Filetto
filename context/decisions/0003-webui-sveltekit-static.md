# ADR-0003: WebUI を SvelteKit 3(静的出力)で作る

## ステータス

採用(2026-10-25)。起案は AI の担い手(Claude)。採否は技術判断者 Takenori Kusaka(プロジェクトのスレッドの判断カードで「SvelteKit 3(静的出力)」を選択)。

## コンテキスト

F-001 Task-6(ゴミ箱の一覧に完全削除までの残日数を表示する。受入基準11・12)で、WebUI の画面が初めて要る。計画(`specs/F-001/plan.md`)は画面を `web/**` に置くとしているが、WebUI の技術は決めていなかった。

制約:

- バックエンドは FastAPI(ADR-0002)。REST の JSON API と MCP を同じ ASGI アプリに置く
- 画面の要件は、原本のツリーの閲覧、ゴミ箱(削除・復元・残日数)、リネーム・移動の履歴、版の履歴、全文検索。完全削除の予告をトースト・ポップアップ・バッジ・メールで通知しない(F-001 受入基準12)
- 保守は1人。配布は Docker compose

比較の材料: `/mnt/project-files/research/reports/WebUI 技術比較 2026.md`(2026-10-25 時点の調査。プロジェクトの共有フォルダ)

## 決定

- WebUI は **Svelte 5 + SvelteKit 3** で書き、`@sveltejs/adapter-static` で静的ファイルへ出力する(SPA。サーバー側の描画は使わない)
- ソースは `web/` に置く。出力は FastAPI から `StaticFiles` で配信し、データは既存の JSON API(`/api/**`)から取る。画面のための別の API の層は作らない
- 版はマイナー版まで固定し、`package-lock.json` をコミットする。依存の導入は `npm ci --ignore-scripts` に限る(インストール時のスクリプトを動かさない)
- Docker はマルチステージにし、Node はビルドの段だけに置く。実行のイメージに Node を入れない

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | 変えられる |
| 変えるとしたら必要なこと | `web/` の画面を書き直す。データは JSON API から取るため、バックエンドは変えずに済む |
| いつまでなら安く変えられるか | 画面が少ないうち(F-001 の画面が揃う前) |

## 非機能への影響

| 項目 | 影響 |
| --- | --- |
| 性能 | 静的配信のため、サーバーの負荷は小さい |
| 可用性 | 影響なし(配信は FastAPI と同じプロセス) |
| セキュリティ | npm の依存(最小 73 パッケージ。テストに Vitest 98・Playwright 3)が加わる。2026-01 に Svelte 系で 5 件の CVE があった。2026-08 の npm ワームは `preinstall` で CI の秘密を盗み `.claude/` に居座った。`--ignore-scripts` と版の固定、依存の監視(`npm audit` か Dependabot)で抑える |
| 運用 | SvelteKit 3 は 2026-10-01 に出たばかりで、直後の更新に追随する作業が要る。CI に Node のセットアップが加わる |

## 影響

- 画面と API が分かれ、画面は JSON API の利用者になる。MCP と同じ API を通るため、経路で挙動が分かれにくい
- CI に Node の段(`npm ci --ignore-scripts`、ビルド、Vitest、Playwright)を足す必要がある。ライセンスの検査(ip-clearance)と脆弱性の検査を npm の依存にも広げる必要がある(現在の検査は Python の依存だけを見る)
- AI の学習データには Svelte 4 / SvelteKit 2 の書き方が多く、古い書き方が混入しやすい。公式の `llms.txt` と MCP サーバーを参照する
- この決定で解決しないこと: CI と Docker の具体的な構成(画面を初めて足す変更で決める)、E2E を CI の必須にするか
