# P-001 Filetto

## 案件の目的

個人が自分の PC に 1 コマンド(`docker compose up`)で立てられ、**ファイルを置いた瞬間から人にも AI にも検索可能になる**、維持コストゼロのファイル倉庫を作る。

人向けの入口は Windows Explorer / Google Drive 相当の**ファイル操作が一級市民**の UI(階層・ドラッグ&ドロップ・リネーム・削除・プレビュー)。AI 向けの入口は同一のファイル資産に対する**セマンティック検索と MCP アクセス**。この 2 つが同じ実体を共有していることが本プロダクトの価値であり、既存の RAG 製品(Onyx / AnythingLLM / RAGFlow / OpenDocuments)との差である。既存製品はいずれも「取り込み口」であってエクスプローラーではない。

対象は非エンジニアを含む個人利用者。「AI に読ませたい資料の置き場」を、エンジニアの手を借りずに用意できる状態を最初の成功条件とする。

## 暗黙の前提

G-2 で正式に登録する。現時点で PO が置いている前提は次のとおり。

| # | 前提 | 崩れたときの影響 |
| --- | --- | --- |
| 1 | ~~Graphify(Apache-2.0)が汎用ドキュメントに対して実用的な精度で使える~~ → **検証済み(2026-08-12 / [#1](https://github.com/Takenori-Kusaka/Filetto/issues/1))。Graphify は中核に据えない**。スキル手順どおりなら 8/10 に達するが、LLM バックエンドが必須で「維持コストゼロ」が成立しない。また .xls / .doc / .pptx が非対応 | — (解消) |
| 2 | 外部 API・ベクトル DB なしで実用的なセマンティック検索が成立する | **成立する見込みが実測で得られた**(パース + 日本語形態素 + BM25 で 8/10 / 31秒 / $0 / 外部通信なし)。ただしパース層の確定待ち([#5](https://github.com/Takenori-Kusaka/Filetto/issues/5)) |
| 3 | 利用者は Docker を起動できる | 「非エンジニアに広げる」という目的と衝突しうる |
| 4 | AGPL-3.0 でも個人セルフホストの採用は妨げられない | 採用が伸びない場合、ライセンス方針の再検討が必要([[ADR-001]] で代替案を記録する) |

## 事業ステージの現在地

| 項目 | 値 |
| --- | --- |
| 現在のステージ | **S1 価値確立**(ただし SG-0 の「技術的実現性が確認されている」が未通過) |
| 未通過の移行ゲート | SG-0。[Filetto#1](https://github.com/Takenori-Kusaka/Filetto/issues/1) の検証結果をもって判定する |
| 次の移行ゲート | SG-1。判定基準に **「拡大に耐えるアーキテクチャが確定している」** を含む |

S1 を選ぶ理由は、Filetto 完了後に Chat / Auth を別マイクロサービスとして開発し、Docker アーキテクチャへ合成する計画があるためである。S0(探索)へ落とすと G-2 が G-4 へ統合され、G-3 は主要な選択のみ、ADR も主要な選択のみとなり、**後続サービスと合成するための境界設計とインターフェース契約が記録に残らない**。合成の前提が失われるため、S0 へは落とさない。

### 合成を見据えて MVP に必ず含めるもの

SG-1 の「拡大に耐えるアーキテクチャが確定している」を満たすため、次を MVP の確約範囲(SC-M)に含める。

| # | 含めるもの | 理由 |
| --- | --- | --- |
| 1 | 対外インターフェース(REST API / MCP)の契約を ADR で固定する | 後続の Chat / Auth が依存する境界。あとから変えると全サービスに波及する |
| 2 | JWT クレームの契約(クレーム名・スコープの表現・検証の責務分界)を ADR で固定する | 認証基盤は別サービスへ外出しするため、境界の合意が先に要る |
| 3 | Filetto 単体で価値が完結すること(Chat / Auth なしで動作すること) | 単体で価値が出ないなら、マイクロサービスとして切り出す理由がない |
| 4 | 恒久層コンテキスト(用語集・設計標準)の整備を開始すること | S1 の要件。後続サービスが同じ語彙を使えないと合成時に破綻する |

## PO が確定させた事項(2026-08-12)

| # | 論点 | 決定 |
| --- | --- | --- |
| A | スコープ | Explorer + 検索の**単体 OSS マイクロサービス**。Auth / User / Chat / LiteLLM / Claude Code はこのリポジトリの対象外 |
| B | ライセンス | **AGPL-3.0** |
| C | 最初のユーザー | **個人が自 PC に Docker で立てる** |
| E | 検索エンジン抽象化 | **インターフェースのみ定義し、実装は Graphify 単一**。1 リポジトリ 1 インデクサとし、混在ケースは初版で非対応と明記する |
| F | 認証 | 認証基盤自体は別の OSS マイクロサービスとして分離。Filetto 側は**JWT クレームによるファイルアクセススコープ制御**を前提に実装する |
| G | 状態通知 | ポーリングによる UI バッジ表示と、SSE/WebSocket によるリアルタイム通知の**両方**を提供する |
| — | 削除の可逆性 | 物理削除ではなく**ゴミ箱方式(復元可能)**とする。リネーム・移動にも元に戻す手段を持たせる。これにより安全重要度を CL0 に下げる |
